# 2026-08-29 工作记录

## 平板管控系统（PadGuard 家长控制端）— 编译修复

目标：让项目在 Android Studio 成功编译（Mock 数据模式，无后端）。本轮修复了阻塞 `assembleDebug` 的多处问题。

### 关键根因与修复
1. **Room 坐标错误**：`app/build.gradle.kts` 写了 `androidx.room:runtime:2.6.1`（应为 `androidx.room:room-runtime`）；且 Mock 阶段 LocalDataSource 用 DataStore 不用 Room → 直接移除 app 的 Room 依赖。
2. **NetworkModule 反向依赖**：原 `core:network/NetworkModule.kt` 引用 app 模块内的 `com.padguard.data.api.*`（core 不能依赖 app），且 core:network 未声明 Hilt，MoshiConverterFactory 的 import 路径也写错 → 将 NetworkModule 移动到 `app/src/main/java/com/padguard/parent/di/NetworkModule.kt`，并把 core:network 的网络库依赖由 `implementation` 改为 `api`（使 app 可见 Retrofit/Moshi/OkHttp）。
3. **ApiInterfaces.kt 截断 + 重复类**：该文件被截断在 PolicyApi 中间，且与独立的 PolicyApi.kt 形成 `interface PolicyApi` 重复定义 → 重写为仅含 AuthApi/DeviceApi/MonitorApi；PolicyApi 独立保留。
4. **语法错误**：`PolicyApi.kt` 部分 `Response<ApiResponse<Unit>` 缺 `>`；`LocalDataSource.kt:125` `Result<Unit)` 应为 `Result<Unit>`。

### 后续修复（用户贴回 `:app:kspDebugKotlin FAILED` 日志后）
- **根因**：上一轮用 `replace_all` 把 `Response<ApiResponse<Unit>` → `Response<ApiResponse<Unit>>` 时，原文件里 line 35 / line 77 本来已是双 `>`，被叠加成三 `>>>`。Kotlin 解析器遇到多余 `>` 后迷失，在行尾报 `Expecting member declaration`（line 35:35、line 77:35）。其余 7 处单 `>` 被正确补成双 `>`。
- **修复**：把 line 35 (`setGlobalDailyLimit`) 与 line 77 (`lockScreen`) 的 `Response<ApiResponse<Unit>>>` 改回 `Response<ApiResponse<Unit>>`。
- **预检**：`>>>` 全量扫描确认除 `Response<ApiResponse<List<X>>>`（合法三 `>`，List 内嵌）外无非法三 `>`；6 个 Api 文件（Auth/Device/Monitor/Policy/Statistics/Alert）全部泛型配平；Api 引用的 ~34 个 DTO/请求类型均在 `data/model` 或 `domain/model` 中定义，无缺失。
- 现状：PolicyApi 修复后 `:app:kspDebugKotlin` 应能过；若 `:app:compileDebugKotlin` 仍报错需用户贴新日志。

### 第二批修复（用户贴回 `:app:compileDebugKotlin FAILED` 日志后）
构建进度推进到 `:app:compileDebugKotlin`，暴露 6 类错误，已全部修复：
1. **LocalDataSource 缺 domain import**：`RepositoryInterfaces.kt`（包 `com.padguard.domain.repository`）内直接定义了 domain 实体 `DeviceGroup`/`LocationInfo`/`PolicyTemplate`/`WebActivityStats`/`DomainVisit`/`ViolationStats`/`DailyViolation`（不在 `domain/model`）。LocalDataSource 只 import 了 `com.padguard.domain.model.*` → 补 `import com.padguard.domain.repository.*`。其余 7 处 "Cannot infer type" 为级联，随之消失。
2. **NetworkModule.kt:59 OkHttp4 弃用（ERROR 级）**：`original.method()`/`original.body()` getter 已 deprecated → 改为属性 `original.method`/`original.body`（Builder 的 `.method(...)` 仍可用）。
3. **Theme.kt `PadGuardColors` 自引用递归**：`val OnlineGreen = OnlineGreen` 的 RHS 解析到对象自身成员 → 改为全限定名 `com.padguard.presentation.ui.theme.OnlineGreen` 等，指向文件级私有 Color 常量。
4. **CommonComponents.kt 4 处 "recursive problem"**：全部源自 #3 的 `PadGuardColors.SuccessGreen` 等无法推断类型 → 随 Theme 修复自动消除，无需改 CommonComponents。
5. **LoginScreen.kt 缺 Compose import**：`Color` / `background` 未导入 → 补 `androidx.compose.ui.graphics.Color` 与 `androidx.compose.foundation.background`。
6. **HomeScreen.kt 三处**：
   - 缺 M3 pull-to-refresh API → 补 `import androidx.compose.material3.pullrefresh.*`（`rememberPullToRefreshState`/`PullToRefreshContainer`/`pullRefresh` 在 material3 1.2+ 的该子包内）。
   - `FeatureItem` 重复定义：CommonComponents 与 HomeScreen 各有一份字段相同的 `FeatureItem`，HomeScreen 把自家 `home.FeatureItem` 传给期望 `components.FeatureItem` 的 `FeatureGridItem` → 删除 HomeScreen 本地定义，改 import `com.padguard.presentation.ui.components.FeatureItem`。
   - `items.size.lastIndex` 笔误（`size` 是 Int 无 lastIndex）→ 改为 `items.lastIndex`。

### 第三批修复（pull-to-refresh @OptIn 闭合）
- `HomeScreen.kt` 之前已把 import 包名由错误驼峰 `androidx.compose.material3.pullrefresh` 改为全小写 `androidx.compose.material3.pulltorefresh`，并把拉刷从 M2 的 `Box{ ... .pullRefresh(...) }` 改为 M3 的 `Box(.nestedScroll(pullRefreshState.nestedScrollConnection)){ PullToRefreshContainer(modifier=Modifier.align(Alignment.TopCenter)); LazyColumn() }`。
- **剩余点**：`rememberPullToRefreshState` / `PullToRefreshContainer`（material3 1.3.x 的 `pulltorefresh` 子包）被标记 `@ExperimentalMaterial3Api`，而 `HomeScreen` 原注解仅 `@OptIn(ExperimentalFoundationApi::class)` → 编译会报 "This declaration needs @OptIn(ExperimentalMaterial3Api::class)"。
- **修复**：line 49 改为 `@OptIn(ExperimentalFoundationApi::class, ExperimentalMaterial3Api::class)`（`ExperimentalMaterial3Api` 经 `import androidx.compose.material3.*` 已可见，无需新增 import）。grep 全仓确认仅 `HomeScreen.kt` 用到该 M3 拉刷 API，修复局部收敛。
5. **跨包未导入**：`LoginScreen`/`HomeScreen` 使用了 `LoginViewModel`/`HomeViewModel` 但未 import（声明包为 `com.padguard.presentation.viewmodel`）；`MainActivity` 误导入 `com.padguard.parent.presentation.ui.*`（应为 `com.padguard.presentation.ui.*`）。
6. **资源缺失/运行时崩溃风险**：Manifest 引用不存在的 `@mipmap/ic_launcher*`（已新建 `res/drawable/ic_launcher.xml` 矢量图标并改引用 `@drawable/ic_launcher`）；删除会导致启动崩溃的 `androidx.startup.InitializationProvider`（无对应依赖）。
7. **core:* 模块缺 AndroidManifest**：common/database/ui/network 均无 manifest → 各补一个最小 manifest。

### 架构注意（避免再次踩坑）
- 包名约定不统一：声明包为 `com.padguard.*`（无 parent），但目录在 `com/padguard/parent/*`。Kotlin 允许包≠目录，只要 import 与目标**声明包**一致即可。
- API 接口集中在 `app` 模块 `com.padguard.data.api`（不放到 core:network），故 Hilt 网络模块必须放在 app 模块。
- 本环境无 gradlew/gradle on PATH，无法在此跑构建；需用户在 Android Studio 本地 `assembleDebug` 验证，并把新报错贴回。
