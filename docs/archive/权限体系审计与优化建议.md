# PadGuard 权限体系审计与优化建议

> 生成日期：2026-10-09
> 审计范围：护航成长（孩子端）权限与防绕过体系 / padguard-server 鉴权链 / 护航控制端（家长端）消费链
> 定位前提（已拍板）：① 只上线国内渠道，不考虑 Google Play 政策；② 目标用户为低龄小朋友，不考虑懂 adb 的绕过者；③ 主线为不依赖 Device Owner 的软件级防绕过
> 分析方式：两路并行代码级审计，所有结论附文件路径与行号证据

---

## 一、审计总结论（一句话版）

**能力矩阵、篡改自检、密码体系、无障碍拦截的"地基"都在且质量高，但有三条关键链路断了**：
1. 孩子端无障碍/权限失活 → **家长无感知**（告警链路断裂，这是无 DO 主线下最大的洞）
2. 服务端存在 **Geofence 全线越权（IDOR）**、**JWT typ 混用**、**管理端读权限未落地** 三个高危鉴权缺口
3. 家长端**风险告警没有任何 UI 出口**——服务端 12 类告警生成并推送了，家长端却无页面消费

## 二、孩子端权限体系现状（无 DO 视角）

### 2.1 已具备（地基扎实，超出竞品平均水准）

| 能力 | 证据 |
|---|---|
| 四档能力矩阵 + 降级显式记录（不黑洞） | `DeviceAdminBridge.kt:111-138`，LEGACY 降级走 `EnforceReport.markUnsupported` |
| 无障碍三类拦截闭环：设置页顶回 / 安装器弹密码 / 受管应用拉回 | `OperationGuardAccessibilityService.kt:141-157, 113-129` |
| 9 个 ROM 设置包 + 12 个安全中心包清单（MIUI/华为/ColorOS/vivo/三星/一加/realme） | `OperationGuardAccessibilityService.kt:172-182`、`AppGuardPolicyStore.kt:259-272` |
| 护航密码：SHA-256 协议哈希、错 5 次锁 5 分钟、10 分钟解锁窗口、明文不出网 | `GuardPasswordManager.kt:91-159` |
| 篡改自检五项（时钟/权限降级/USB 调试/Root/限制丢失），降级自动 force 重压 | `TamperDetector.kt:59-137`、`PolicyEngine.kt:360-362` |
| 黑名单前台 15s 采样兜底拦截 + 上报 | `PolicyEngine.kt:283-305` |
| 开机/覆盖安装自启 + 国产快速开机广播 + 看门狗 | `BootReceiver.kt:47-52` |
| 防砖保护（launcher/IME/拨号器强制放行）+ 防自杀指令 | `AppGuardPolicyStore.isSystemCritical:195-220`、`AppInstaller.kt:87` |

### 2.2 关键缺口（对照"格雷盒子式无 DO 防绕过"目标）

| # | 缺口 | 现状证据 | 后果 |
|---|---|---|---|
| C1 | **无障碍被关闭 → 家长零感知** | `GuardA11y.isEnabled` 探测齐备但只接了本地"我的"页 banner；TamperDetector 检测清单（:59-72）无此项 | 无 DO 主线的**核心防线失活后整个软拦截体系静默死亡**，孩子端不再拦任何东西 |
| C2 | **ROM 卸载器覆盖不全** | 缺 `com.oplus.*`（ColorOS 新包名）、`com.huawei.appmarket`、`com.bbk.appstore`；只按包名匹配无类名级区分，安装/卸载开关 OR 合并无法分别生效（`AppGuardPolicyStore.kt:146-148, 279-285`，第三个条件与第一个重复） | 华为/ColorOS/vivo 设备上"卸载需密码"可能漏网 |
| C3 | **不识别"正在卸载的是自己"** | 拦截逻辑按目标页包名匹配，卸载确认页运行在 packageinstaller 进程中才碰巧被拦，无自身包名特判 | 拦截语义不精确，无法做"卸载 PadGuard 需家长密码、安装其他 App 可放行"的差异化 |
| C4 | **安全模式无运行时检测** | 仅 DO 档有 `DISALLOW_SAFE_BOOT`；LEGACY 下重启进安全模式 = 完全脱管且零告警 | 虽然小朋友不太会，但成本极低应补检测告警 |
| C5 | **默认桌面无引导、无状态监控** | `KidHomeActivity.kt:55` 仅注释"家长手动设置"；无"检测默认桌面≠自己→引导/告警"逻辑 | 最重要的软性圈禁手段没被激活 |
| C6 | **onDisableRequested 只落日志不进告警流** | `PadGuardDeviceAdminReceiver.kt:72` 走普通用量日志通道，不生成告警 | "有人正在拆防线"家长看不到（真正停用后的 PERMISSION_REVOKED 才告警） |
| C7 | **密码试错不上报** | `GuardPasswordManager.verifyWithLimit` 失败仅本地日志（:157） | 暴力试锁行为不可见（虽有 5 次锁定兜底） |
| C8 | **使用情况权限失活无检测** | tick 黑名单兜底依赖 PACKAGE_USAGE_STATS，失活后 fg=null 静默失效，TamperDetector 不检 | LEGACY 兜底静默死亡 |
| C9 | **白名单模式无 DO 时无兜底** | `PolicyEngine.kt:288-290` 明确放弃 | 低龄用户主打白名单的话是产品级空洞 |

## 三、服务端鉴权链现状

### 3.1 结构评价（好的部分）

- 拦截器分层清晰、顺序正确（鉴权 → 订阅闸门 → 业务），排除路径有注释依据
- admin token `scope=admin` 单向强隔离；RBAC 写闸门统一 Service 层 + super 防锁死/防提权护栏完整
- 大部分家长业务 Service 有归属校验（AppManage/Monitor/Statistics/ContentFilter/DeviceMgmt/Unlock 抽查均覆盖）
- 指令 HMAC 签名、支付验签 fail-closed、JWT 密钥已出安装包——方向都对

### 3.2 鉴权缺口（按风险排序，Top 8）

| # | 等级 | 缺口 | 证据 |
|---|---|---|---|
| G1 | 高 | **Geofence/位置全线 IDOR**：四个公开方法均不校验设备归属，任何登录家长可读任意设备实时位置/200 条轨迹、可改写他人围栏 | `GeofenceService.kt:27-72`，入口 `ParentExtendedControllers.kt:24-26, 104-118` |
| G2 | 高 | **管理端读权限未落地**：全部 admin GET 端点无 `require(area,"read")`，RBAC 收窄只对写操作生效 | `AdminController.kt:32-49, 89-94, 113-123, 189-208` |
| G3 | 高 | **家长端风险告警无 UI 出口**：12 类告警服务端生成并推 WS，但家长端 AlertCenterScreen 只消费解锁工单；`AlertApi`/`observeAlerts` 数据层完整却无任何 ViewModel 消费 | `AlertCenterScreen.kt:56-69`、`ApiDataSource.kt:1021-1053` |
| G4 | 高 | **JWT typ 混用**：parseUserId 不验 typ，30 天 refresh token 可当 access 用；access 可当 refresh 无限续期；admin/refresh token 可过家长 WS 握手 | `JwtTokenProvider.kt:62-100`、`DeviceWebSocketHandler.kt:22-33` |
| G5 | 中 | **支付回调路径未排除鉴权**：`/v1/billing/notify` 会被 ParentAuthInterceptor 401，真实网关回调必失败；且 mock-pay-enabled=true 时验签器放行一切回调 | `WebConfig.kt:55-77`、`BillingController.kt:84-104`、`PaymentVerifier.kt:67-70` |
| G6 | 中 | **文件软鉴权三重兜底放行**：无凭证请求、无归属历史文件一律放行 | `FilesController.kt:92, 94, 99` |
| G7 | 中 | **全局无限流**：家长登录/admin 登录/匿名绑定码（6 位、10 分钟窗、无尝试限制）均可脚本爆破 | `AuthService.kt:34-41`、`BindCodeService.kt:25-63` |
| G8 | 中 | **指令状态查询无归属**：`GET /v1/commands/{msgId}` 任何家长可查任意指令 payload | `CommandService.kt:77-85` |

另有：G9 controlMode 语义冲突（服务端存 DEVICE_OWNER/.../LEGACY，家长端按 NORMAL/LEARNING/FOCUS 解析且非法值静默回落 NORMAL——**真实权限等级对家长完全不可见**）；G10 心跳快照的 storage/memory/screen/foregroundApp 字段被服务端 DTO 丢弃；G11 mock-pay 无订单归属校验；G12 deviceToken 无过期无轮换 + 非常量时间比较。

## 四、优化建议（三批，可直接开工）

### 第一批：安全阻塞修复（P0，上线前必须）

**服务端（改动小、收益大，建议先行）**

1. **G1 位置越权**：`GeofenceService` 四个方法补 `userId` 参数 + 归属校验（照抄 MonitorService 的模式），涉及 4 个方法 + 2 个 Controller 入口——约半天工作量
2. **G4 JWT typ**：`parseUserId` 内校验 `typ=access`；refresh 接口单独校验 `typ=refresh`；WS 握手同 access 规则 + 补用户存在性校验
3. **G5 支付回调**：`/v1/billing/notify` 加入 ParentAuthInterceptor 排除名单（注释里写的意图没落进 WebConfig）；确认生产 `mock-pay-enabled: false`
4. **G2 管理端读权限**：为 admin GET 端点统一补 `require(area, "read")`——逐端点机械添加
5. **G7 基础限流**：登录/发码/绑定码三处加简单失败计数限流（内存 Map 即可，不必上 Redis）
6. **G8/G11**：`getCommand` 补归属校验；mock-pay 补 `order.userId == 调用者`

**孩子端（配合无 DO 主线的一处关键接线）**

7. **C1 无障碍失活告警**：TamperDetector 新增检测项（复用 `GuardA11y.isEnabled`），失活 → `ACCESSIBILITY_DISABLED` HIGH 事件 → 走现有 PERMISSION_REVOKED 同款告警链路。**这是全清单性价比最高的一条**——检测代码已存在，只缺接线

### 第二批：无 DO 防绕过补强（P1，1-2 个迭代）

8. **C2 ROM 卸载器适配**：`SECURITY_CENTER_PACKAGES`/安装器清单补 `com.oplus.*` 前缀、`com.huawei.appmarket`、`com.bbk.appstore`；`isInstallerPackage` 去重；建立"真机 ROM 适配表"（MIUI/鸿蒙/ColorOS/OriginOS 各测一台）
9. **C3 卸载自身特判**：无障碍拦截时读取窗口类名/标题区分"卸载确认 vs 安装确认"（国内不受 Play 限制，可做类名/文本匹配），对"卸载 PadGuard"走强制密码、安装确认按家长开关
10. **C5 默认桌面激活**：启动时检测默认桌面 ≠ KidHomeActivity → 弹引导页（跳系统"默认应用"设置）；开机自检发现被改回 → 告警家长。低龄场景下这是不花钱的最大圈禁手段
11. **C4 安全模式检测**：BootReceiver 检测安全模式启动（第三方应用全部禁用即特征）→ 上报告警
12. **C6 停用尝试进告警流**：onDisableRequested 由普通日志改 raise 事件
13. **C7/C8**：密码试错上报（复用事件通道）；TamperDetector 加 PACKAGE_USAGE_STATS 失活检测
14. **C9 白名单兜底决策**：低龄主打白名单的前提下，重估"15s 采样 + 无障碍 launchBlock（默认开）+ 桌面隐藏"的组合兜底，或产品层引导白名单用户走 DO 档

### 第三批：家长端"最后一公里"（P2，决定产品感知）

15. **G3 告警中心落地**：新增风险告警列表页（数据层 `observeAlerts`/`AlertApi` 全部现成，缺的只是 ViewModel + Screen + 路由）；WS 客户端扩展消费 `alert.new`（`UsagePushClient` 自愈基座已备）
16. **G9 controlMode 语义拆分**：按契约对齐表 #7 的决议拆成两个字段——`controlMode`（孩子上报权限等级）与 `sceneMode`（家长设定场景）；家长端设备详情页新增"管控强度"卡（DO/管理员/无权限 红黄绿灯），掉级即红色 + 告警联动
17. **G10 心跳健康度**：服务端 `HeartbeatDto` 补收 storage/memory/screen/pendingLogCount，家长端设备详情页展示"设备健康"面板（权限失活、存储不足可视）
18. **心跳差值告警**：服务端 `applyHeartbeat` 对 controlMode 降级做差值检测 → 生成告警（与孩子端事件链路互为冗余，两条链都通才算闭环）

## 五、验收标准（关键项）

| 项 | 验收方式 |
|---|---|
| G1 | 家长 A 的 token 请求家长 B 设备的 `/location/current`，返回 403/404 |
| G4 | refresh token 调业务接口 401；access token 调 `/auth/refresh` 401 |
| C1 | 孩子端关闭无障碍 → 家长端 60s 内收到告警（轮询）或实时（WS） |
| C2 | 华为/小米/OPPO 真机各自走"设置→应用→卸载 PadGuard"，均弹密码 |
| C5 | 孩子端把默认桌面改回系统桌面 → 家长收到告警；重新绑定流程含桌面引导 |
| G3 | 服务端注入一条 PERMISSION_REVOKED 测试告警 → 家长端告警页可见、可确认关闭 |
| G9 | 未开 DO 的设备在家长端显示"软件级管控（管理员）"而非"正常" |

## 六、优先级总览

```
第一批（P0，安全阻塞）：G1 越权 → G4 JWT typ → G5 支付回调 → C1 无障碍告警
                        → G2 admin 读权限 → G7 限流 → G8/G11
第二批（P1，无 DO 补强）：C2 ROM 适配 → C3 卸载特判 → C5 桌面激活
                        → C4/C6/C7/C8 → C9 白名单决策
第三批（P2，家长感知）：G3 告警页 → G9 controlMode 拆分 → G10 健康度 → 差值告警
```

> 与既有《工程全景分析报告》的关系：本报告聚焦**权限体系**这一个切面，其结论与全景报告的第一批（MQTT/HTTPS/admin 凭据）互补、不重复；两者合并即为完整的上线阻塞清单。
