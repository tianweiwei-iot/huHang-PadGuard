## 二、批次 D 详细设计：S1 broker 认证 + per-device 凭据 + ACL（待确认）

### 2.1 目标与威胁模型

| 威胁 | S1 后的状态 |
|---|---|
| 局域网内任意客户端匿名连 broker，订阅/伪造任意设备指令与数据 | **消除**：无凭据连接被拒 |
| 设备 A 冒充设备 B 收指令（跨设备串台） | **消除**：ACL 按 username=deviceId 收敛到本设备 topic |
| 解绑设备继续收发（总账 W2 根子问题） | **消除**：解绑即从 password_file 移除 + reload |
| payload 级伪造（合法凭据但伪造指令内容） | 不在 S1 范围 —— W1/R5（上行 HMAC）承接，见第四节 |

### 2.2 核心矛盾与决策依据

当初选共享凭据的唯一根因：**Windows 版 Mosquitto 无法热加载 password_file**（DeviceService.kt:47 注释）。P-D2 已拍板 per-device，凭据生效机制是本次设计的核心取舍：

| 方案 | 结论 |
|---|---|
| dynamic-security 插件（$CONTROL 动态加用户，免重启） | ❌ 否决：Windows 官方安装包不带该插件，家庭部署形态不可用 |
| EMQX HTTP 认证 | ❌ 否决：引入新组件，违背家庭部署"双击即用"形态 |
| **写 password_file + 触发 reload（按形态分流）** | ✅ 推荐：home 重启 Mosquitto 服务；docker SIGHUP 热重载 |

### 2.3 设计要点

**① 凭据生成与存储（服务端，改动最小）**
- 未注入共享凭据时 DeviceService 本就生成 per-device 随机密码（`mk_` + UUID），username=deviceId——**孩子端零改动**，bind 响应链路不动。
- S1 只需把"生成"接上"写入 broker"：新增 `MqttCredentialProvisioner`（服务端组件），在绑定成功后、解绑后触发。

**② password_file 写入格式（待确认点 1）**

| 选项 | 优点 | 缺点 |
|---|---|---|
| a) hash 行 `deviceId:$6$salt$hash`（JVM 内实现 mosquitto_passwd 的 SHA-512 格式） | 文件无明文密码 | salt/base64 变体需与 Mosquitto 精确对齐，部署包需一次性实测 |
| b) 明文行 `deviceId:password`（Mosquitto 原生支持）+ 文件权限收紧 | 零格式风险，实现最简 | 密码明文落盘——但 DB 里本就存明文（需下发给孩子端），不增加暴露面 |

**建议 b)**（原则②：主流成熟、少一个自定义 hash 对齐点）；同机文件 + ACL 权限，暴露面与现状 DB 相同。

**③ reload 策略（按部署形态）**
- home（Windows）：`net stop mosquitto && net start mosquitto`（或 sc）。已连设备 Paho 自动重连；触发频率=绑定/解绑，低频，秒级窗口可接受。
- docker（云端）：`docker kill -s HUP mosquitto` 热重载 password_file + acl_file，零断连。
- provisioner 失败语义（待确认点 2）：**建议绑定主链路不被 broker 运维动作阻塞**——provision 失败只记 warn + 走告警通道，绑定照常成功（孩子端本就有 HTTP 降级链路，broker 恢复/重载后 MQTT 自动补上）。反例是 fail-fast 让绑定卡死在 broker 故障上。

**④ ACL：一次配好、永不随设备增删改**

```text
# 服务端账号（读写全部）
user padguard-server
topic readwrite pg/v1/#

# per-device 账号（username = deviceId）：只收自己的下行、只发自己的上行
pattern read  pg/v1/+/down/%u/#
pattern write pg/v1/+/up/%u/#
```

- topic 结构已核实：`pg/v1/{tenantId}/up|down/{deviceId}/{type}`（MqttTopics.kt:4），pattern 前提成立。
- broadcast（`pg/v1/{tenant}/broadcast/+/command`，分组批量指令）ACL 只能到 tenant 粒度——**如实登记**：组级过滤沿用现有服务端语义（契约 §3.2 "由服务端保证只推给组内设备"），S1 不改变该边界，也不在文档中夸大为"已隔离"。
- 设备侧订阅清单（MqttTopics.subscriptions）无需改动。

**⑤ 解绑即撤销**：从 password_file 删除行 + reload，W2 的 broker 侧闭环在同一批完成（hmacSecret 轮换留给 W2 服务端侧）。

### 2.4 待确认 3 点（确认后开工）

| # | 决策项 | 建议 |
|---|---|---|
| 1 | password_file 格式：hash（a）vs 明文+文件权限（b） | **b**，部署包首装实测一次即锁定 |
| 2 | provision 失败语义：绑定不被阻塞（warn+告警）vs fail-fast | **不阻塞**，稳定性优先 |
