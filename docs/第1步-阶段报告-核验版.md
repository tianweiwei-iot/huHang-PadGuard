## 2. 当前全部业务逻辑

### 2.1 主体与角色（代码事实）

- `users`：家长账号（`phone` UNIQUE、`role`、`scene_type`、`status`、`token_version`、`login_fail_count` / `login_locked_until`）。**孩子不是独立主体**，以 `deviceId` + `deviceToken` 作为唯一身份。
- `devices`：一台设备挂一个 `user_id`；`device_sn` **无 Flyway 唯一约束**（仅手工脚本 `scripts/add_device_sn_unique_index.sql`）。
- `admins` + `admin_roles` + `admin_role_overrides`：5 个内置角色 `super/ops/cs/finance/audit`，权限点 `area:action`，判定优先级 override > 自定义角色 > 内置默认。
- **未找到** 学校 / 班级 / 学生 / 多监护人 / 租户 实体；`scene_type` 仅为场景标记。

### 2.3 业务流程图（文本版）

**① 入网与绑定**
```
家长 App ──POST /v1/devices/enrollments──> enrollment_sessions(PENDING, revision)
   │                                          │ 3s 轮询 / WS device.enrolled
   │<── 配对码 / 二维码 ────────────────────────┘
孩子端 ──POST /api/v1/device/bind(码 + 设备指纹)──> 限流(8/min) + bindByAccount 或 bindChild
   │                                              ├─ 事务内：用户行锁 → 设备数上限 → 保存 → 签发 deviceToken
   │                                              └─ enrollment: PENDING→BOUND（乐观锁冲突即拒）
   └<── deviceToken + deviceId（服务端 UUID）────┘
孩子端 ──首启一次性同意(协议 + 权限 + DA + 采集授权)──> AGREEMENT 留痕
```

**② 策略下发与本地强制执行（离线红线主链路）**
```
家长改设置 ──PUT/POST /v1/policies|/v1/devices──> PolicyService
   └─ 事务：devices 行锁 → nextVersion → 追加 policies 新版本行 → 指令/策略变更通知
        ├─ MQTT: pg/v1/{tenant}/{down}/{deviceId}/policy
        ├─ WS 推送家长端
        └─ 兜底：孩子端 GET /policy + 每 4 次心跳强制 HTTPS 做 policyVersion 对账
孩子端 CommandGate(签名/过期/幂等) → PolicyRepository.save(仅 version 更大) → 加密本地镜像
   └─ GuardService tick → PolicyEngine.resolveEffectivePolicy(effectiveFrom/To)
        → minorMode 派生基线 → 8 个 Enforcer 顺序施加 → LockController / 无障碍 / VPN / 悬浮窗
   └─ 离线：本地受信时钟 + 精确边界闹钟 + UsageSession 快照，不依赖服务端
```

**③ 远程指令与回执闭环**
```
家长下发 → commands(msg_id UNIQUE, PENDING, expiresAt)
   ├─ MQTT QoS1 下行（cleanSession=false）
   └─ 设备离线 → 留在库中等 GET /api/v1/device/commands?since= 拉取
孩子端 → CommandGate 验签/防重放 → CommandRepository.tryClaim 幂等 → CommandExecutor
   → EngineEffect → 平台副作用 → CommandAck
   → HTTPS /device/ack（失败进 AckOutbox：JSON-Lines + tmp/rename 原子写 + 上限丢最旧）
服务端 → 更新 commands 状态 → 家长端 GET /v1/commands/{msgId} 回显（15s 超时）
过期 → ExpiredCommandSweeper 清理
```

**④ 计时 / 锁屏 / 审批**
```
TimeProvider.now()（单调钳制 + 冷启动基线补偿）→ ScheduleEvaluator(补班日优先/跨午夜/UNLOCK 优先)
   → 边界时刻 → BoundaryAlarmClock(ELAPSED_REALTIME_WAKEUP) → LockBoundaryAlarmReceiver
   → LockController 锁原因集合 {REMOTE, SCHEDULE, CURFEW, DAILY_LIMIT, APP_LIMIT, EYE_CARE}
孩子申请解锁/延时 → unlock_tickets / usage_delay_tickets(PENDING)
   → 家长端全局弹窗(10s 轮询 + WS) → approve / reject / dismiss
   → 服务端下发 TEMP_UNLOCK 或延长 usage_sessions.extended_minutes
```

**⑤ 上报 / 告警 / 统计**
```
孩子端 LogRepository(pending 队列, 上限 5w) → /logs /events /locations /heartbeat /apps
   → IngestService → usage_logs / device_events / location_tracks / installed_apps
   → AlertService(10min 冷却) → alerts → 家长端告警中心 + CRITICAL 本地通知
   → UsageAggregator 分页折叠 → /v1/statistics/*
```

**⑥ 计费与支付**
```
家长 → POST /v1/billing/orders(PENDING) → WeChatPayClient APP 下单 + 二次签名(RSA)
   → 微信支付 → POST /v1/billing/notify（验签 + AES-GCM 解密 + 防重放 ±5min + SUCCESS 才入账）
   → payment_orders.PAID → subscriptions 延长 / 开通 → EntitlementGate 放行设备数与功能
   → 退款 POST /v1/admin/billing/orders/{no}/refund（**当前不回收已发放权益**）
```

## 8. 架构缺陷：两套方案

### 方案 A · 低成本快速修复版（保持单体 + 单实例，推荐先做）

- 策略回滚：新增 `policy_versions` 只读查询 API + 「回滚 = 取历史快照内容、分配**新版本号**重发」（绕开设备端只接受更高版本的约束），附回滚审计；
- 批量下发：新增 batch API，服务端扇出 + 批量任务状态聚合，复用 `PolicyVersions` 行锁；
- 指令可靠性：离线补发 / 上限 / 死信 / broker 不可达告警（**并行会话正在做，需验收后并入**）；
- 合规端点：撤回同意（含设备离线时的本地停采开关）、导出、注销、申诉工单 + append-only 审计；
- 安全：家长端默认改 `https://` + 域名可配；`/v1/files/**` 收紧；短信发码显式失败；MQTT 上行设备绑定复测；
- 稳定性：全局异常/超时/熔断/限流复核、索引与事务复核、监控埋点最小集；
- 明确写入部署约束：**仅单实例**，并在文档中标注多实例前必须完成方案 B 的状态外置。

**代价**：小，可在现有 24 轮基线上增量交付；**收益**：满足 ≤500 台试点上线。

### 方案 B · 长期重构版（多租户 / 家校 / 多机型规模化）

- 领域重建：`tenant(family|school) → org → class → student/guardian`，所有 `user_id` 改挂 `tenant_id + subject_id`，RBAC + ABAC；
- 指令中台：持久化事件流（Outbox / Kafka）+ 至少一次投递 + 上线重放 + 死信 + 幂等消费，MQTT 降级为纯传输通道；
- 策略：不可变快照 + 按设备/分组百分比灰度 + 一键回滚 + 定时生效调度器 + 冲突裁决；
- 数据：冷热分离、分区表、媒体转对象存储、只读副本、软删除与法定留存；
- 契约工程化：KMP 共享契约模块 + OpenAPI 生成客户端 + 契约 CI 门禁（消除手工抄写）；
- 设备适配：`DeviceCapability SPI`（能力探测 → 降级矩阵 → 厂商 DPC 插件）；
- 多实例：分布式锁 / Redis 限流 / 集中在线注册 / KMS 托管密钥 / 集中审计。

**代价**：大，必须等 `⟦TBD-1/2⟧` 业务口径定型后分阶段立项；**收益**：才能承接家校共育与更多平板机型、厂商 DPC。

> 建议路径：**A 先闭环上线阻断项 → B 按拍板结果分阶段迁移**。
