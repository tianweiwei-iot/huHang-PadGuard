## 二、密钥门禁现状（审计结论：整体达标，仅 E-01 需修）

经全量审计，敏感凭证**均走环境变量注入或运行时生成，未硬编码进仓库**：

- **JWT 密钥**：`padguard.jwt.secret` 默认空 → 首次启动随机生成并写入 `config/jwt-secret.txt`（**不进安装包**），多实例部署用 `PADGUARD_JWT_SECRET` 注入。✓
- **高德 Web Key**：`${PADGUARD_AMAP_WEB_KEY:}`。✓
- **邮件 SMTP**：username/password 走 `${PADGUARD_MAIL_USERNAME:}` / `${PADGUARD_MAIL_PASSWORD:}`。✓
- **微信支付**：`app-id/mch-id/serial-no/api-v3-key/private-key-pem/notify-url` 默认全空 → fail-closed（未配置则回调拒收、下单报错）；支持 `private-key-path` 文件挂载。✓
- **文件/资源 base-url**：`${PADGUARD_BASE_URL:}`。✓
- **孩子端/家长端接入点**：`BASE_URL` / `MQTT_BROKER` 在 release 构建期经 `-PBASE_URL`/`-PMQTT_BROKER` 注入（见长期记忆构建要点）。✓
- **运维初始口令文件**：落在 `uploads/`（用户媒体目录），可经 `PADGUARD_PARENT_INITIAL_PASSWORD_FILE` 重定向到 secrets 卷。✓

唯一缺口即 **E-01**：base `spring.datasource` 的 `username/password` 写了字面量 `padguard`，docker 档继承该基块 → 口令随仓库落盘。

## 三、修复计划与改动位置

### 3.1 E-01：数据库口令改为环境变量注入

**修复**：base `spring.datasource` 改为

```yaml
username: ${PADGUARD_DB_USERNAME:padguard}
password: ${PADGUARD_DB_PASSWORD:padguard}
```

- `home` / `local` 档用 H2 文件库（`sa`/空口令，本地库无远程暴露），不受影响。
- docker / k8s 生产部署经 `PADGUARD_DB_USERNAME` / `PADGUARD_DB_PASSWORD` 注入强口令；默认值 `padguard` 仅作「docker-compose 一键起 demo」占位，并在注释中明确「生产必须覆盖，否则库裸奔」。
- 位置：`application.yml` 基块 `spring.datasource`

### 3.2 E-02：微信私钥文件挂载入口显性化

**修复**：在 `padguard.billing.wechat` 下补 `private-key-path:` 并加注释，引导生产改用文件挂载而非内联 `private-key-pem`（私钥不进环境变量、不进镜像层）。
- 位置：`application.yml` `padguard.billing.wechat`

### 3.3 E-03：OpenAPI（依赖未缓存，转为文档化待办）

**现状**：`build.gradle` 无 `springdoc-openapi` / `springfox` / `knife4j` 依赖，且本地 Gradle 缓存（`~/.gradle/caches`）**未包含** `springdoc-openapi-starter-webmvc-ui` → 在离线构建（`--offline`）下无法新增该依赖，强加会令编译失败。

**标准化接入步骤（待联网构建环境执行）**：
1. `build.gradle` 增加 `implementation("org.springdoc:springdoc-openapi-starter-webmvc-ui:2.x")`。
2. `application.yml` 加 `springdoc.api-docs.path: /v3/api-docs`、`springdoc.swagger-ui.path: /swagger-ui.html`，并**务必把这两个路径放进 `WebConfig` 拦截器排除列表之外**（当前 `/v1/**` 与 `/api/v1/**` 皆需鉴权，不放开则 swagger 探不到 schema）。
3. 对鉴权头加 `@Parameter(hidden=true)` 或在 `OpenAPI` Bean 里预设 `securityScheme`（Bearer），避免生成的文档缺少鉴权示例。
4. 因本项目为私域 API，建议 swagger-ui 在生产以 `springdoc.swagger-ui.enabled=false` 默认关闭，仅联调/预发档开启。

> 未擅自加入依赖以免破坏离线门禁。该项是**外部依赖阻塞**（需联网拉包），列为 Step7 残留，待有网络时一次性补齐。

### 3.4 E-04：四环境配置矩阵（文档化）

现有三档 profile 已覆盖四类逻辑环境，无需新增冗余 profile：

| 逻辑环境 | profile | 数据库 | MQTT | 密钥来源 | 用途 |
|---|---|---|---|---|---|
| 开发联调 | `local` | H2 文件库 | 关 | 随机生成 / 空 | 本机单 JVM 起服务联调 |
| 单机生产 | `home` | H2 文件库 | 关（HTTP 轮询兜底） | 首次启动随机生成 JWT 密钥落盘 | **发布包正式档位**（私域/家庭交付） |
| 集群生产 | `docker` | PostgreSQL + Flyway | EMQX | `PADGUARD_DB_*` / `PADGUARD_JWT_SECRET` / `PADGUARD_BILLING_WECHAT_*` 等环境变量注入 | 容器编排多实例 |
| 测试/预发 | 复用 `docker` + 测试数据 | PostgreSQL | EMQX | 同集群生产，独立库实例 | CI / 验收 |

关键工程化控制（已落地，复核确认）：
- `home` 不在 `DEV_PROFILES` 内 → 所有生产红线闸门（mockPay 拒绝、短信免密拒绝、演示账号不播种）对 `home` 全部生效。
- `home`/`local` 用 `ddl-auto: update` + `flyway.enabled: false`；`docker` 用 `ddl-auto: none` + `flyway.enabled: true` → 生产 schema 由迁移单一来源拥有。
- 所有 secret 经 `${PADGUARD_*:}` 注入；仓库内不出现真实凭据（E-01 已收口）。

> 若运维确需独立「预发」profile（与集群生产完全隔离的配置默认值），可后续新增 `on-profile: staging` 文档块，本步不强行增加以免维护面膨胀。
