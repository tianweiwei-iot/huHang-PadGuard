# 法务审核意见：家长端合法合规（2026-11-25）

> 审核人：公司法务（内部合规审查）
> 审核对象：护航控制端（家长端，`com.padguard.parent`）、护航成长（孩子端）、PadGuard 服务端、管理后台、配套法律文本
> 审核依据：《个人信息保护法》（PIPL）、《未成年人保护法》《儿童个人信息网络保护规定》《数据安全法》《消费者权益保护法》、国内主流 Android 应用市场审核规则
> 性质：**内部合规意见**，不替代外部律师出具的正式法律意见书。

---

## 一、总体结论

| 维度 | 裁定 |
|---|---|
| 法律文本与事实一致性 | **整改后 GO**（v2.0 已消除虚假陈述；主体信息仍待填写） |
| 家长端应用市场上架 | **NO-GO**——仍缺运营主体信息、PIA、备案/软著、可公开协议 URL、审核账号 |
| 未成年人个人信息处理 | **整改后条件 GO**——代码层硬闸门已落地（v2.0 协议 + 守卫总闸 + 全文勾选 + 契约锁）；仍需真机验证升版后的停采/恢复链路 |
| 消费者保护（付费/退款） | **整改后 GO**——用户协议与 UI 已如实告知；客服退款流程需留痕 |

**最重要的判断**：此前把问题定性为"代码合规 GO、只差外部资质"是不准确的。
本项目存在**法律文本主动作出与事实相反陈述**的情形，这比"缺一份文件"更严重：
一旦用户或监管据此主张，开发方需就虚假告知承担相应责任。本轮已优先纠正。

## 二、P0 级发现与处置

### P0-1 隐私政策主体陈述与事实冲突（已修文本，主体信息待填）

- **原声明**：`隐私政策.md` v1.0 第 23—25 行——"开发方不运营任何服务器""不接收、不存储、不接触任何设备数据"
  "个人信息处理者是家长本人，而非本应用开发方"。
- **核实事实**：
  1. 项目存在已购买并运行的阿里云生产服务器（`docker-compose.prod.yml:1-2`、
    `docs/控制端手机适配与云服务器迁移计划.md:54,201`），官方托管形态客观存在；
  2. 管理后台 `/v1/admin/parents`、`/v1/admin/devices` 按 RBAC 读权限全量查询家长账号、
    设备、家长手机号与今日用量，客服/运营/审计等内置角色均有全领域 READONLY（`AdminModels.kt:202-224`）；
  3. 项目历史记录显示曾通过 admin 接口查询真实儿童设备数据（`.workbuddy/memory/2026-11-11.md:100-101`）。
- **法务定性**：PIPL 第 17 条要求真实、准确、完整告知处理者身份与处理方式。
  上述声明构成**不实告知**，且使"开发方不接触数据"成为对监管与用户的事实性误导。
- **裁定**：采用**商业化上架口径**——官方托管形态下运营方为处理者；自建形态下家长为处理者。
  不再使用 v1.0 绝对化表述。v2.0 已如实披露管理后台在权限控制与审计下的客服/运维访问。
- **剩余动作**：`隐私政策.md` 第十节、`用户协议.md` 第一条/第十条中的
  【上架前填写：运营主体全称/统一社会信用代码/地址/管辖地】必须由运营方填写，
  并与应用市场开发者主体、ICP/App 备案主体一致。**未填完不得提交审核。**

### P0-2 孩子端协议同意未形成硬闸门（已修，待真机回归）

- **声明与事实**：v1.0 第四节称"孩子端首次启动必须展示政策与监护协议，经明确同意后方可启用守护能力"。
  实际：
  - 同意状态有持久化（`AuthRepository.kt:182-188`、`PermissionGranter.kt:219-225`），
    但 `GuardService` 启动只检查"是否已绑定"（`GuardService.kt:1666`），不检查协议同意；
  - `GuardService.start()`（`:3685-3693`）被开机、守护、绑定等 20+ 处无条件调用；
  - 首次装机页 `OneTimeConsentScreen` 的"同意并开始授权"按钮未展示政策全文，
    全文弹窗只在已进入主页后挂载（`MainActivity.kt:337`），此时守卫已在运行；
  - 历史审计 `docs/权限与安全总账.md:75` 早已列为 W7（Should，未修）。
- **法务定性**：对不满十四周岁儿童个人信息的处理，PIPL 第 31 条与《儿童个人信息网络保护规定》
  要求取得监护人**同意**；同意须在充分知情前提下作出（第 14 条）。
  "政策声称必须同意、系统实际不阻断"使同意的法律效力存疑，并使告知内容本身失实。
- **裁定**：**从 Should 升级为上线阻断**，必须在公开上线前实现：
  1. 首次启动/首次绑定流程中展示协议与隐私政策全文（或可展开查看），监护人主动确认后才落库；
  2. `GuardService` 启动与采集链路读取同意状态，未同意/协议升版未重新同意时不启动采集；
  3. 孩子端已有 `consentRevoked`（家长撤回监控）闸门要保留，两者叠加而非互相替代；
  4. 补契约测试锁住"未同意不采集"，防止回退。
- **需产品确认**：该改动会改变首次启动交互（当前"先授权后看协议"），
  需产品确认文案与流程后由工程实施。法务不接受"仅改文案不改行为"的替代方案。
- **产品已拍板并工程落实（2026-11-25）**：
  1. `CURRENT_AGREEMENT_VERSION` 由 1.0.0 升到 **2.0.0**，存量设备必须重新明示同意；
  2. `GuardService.observeBinding()` 由单流 `isBound` 改为
     `combine(isBound, isAgreementAccepted)` 双流，统一走纯函数 `guardActive(bound, agreed)`；
     闸门关闭时停 MQTT（`remote.stop()` + `transportStarted` 复位）、停周期定位、
     释放全部系统管控并置 `guardState=false`；重新开闸时补启定位与本地策略；
  3. `bootstrap()` 的缓存策略落地与定位启动同样加同意检查，杜绝开机首帧"先管控后同意"；
  4. 孩子端内置协议与隐私政策全文按 v2.0 事实口径重写（处理者双形态、RBAC+审计下的
     客服运维访问、30/90 天保存期限、撤回路径、软管控能力边界、局域网明文风险）；
  5. 首次装机 `OneTimeConsentScreen` 完整展示两份文本并新增显式勾选，未勾选无法点同意；
  6. 闸门关闭分支区分"真解绑"与"仅协议未同意"：只有前者调用 `releaseControl()`，
     否则一次协议升版就会 relinquish Device Owner / 设备管理员（通常需恢复出厂才能重预置），
     造成不可逆降级；未同意时保留设备身份与玻璃球，并恢复管理台入口供家长重新确认；
  7. 新增 `AgreementHardGateContractTest`（8 例），以纯函数语义 + 源码接线扫描双层锁定，防回退。
- **与既有闸门的关系**：`consentRevoked`（家长撤回采集）仍独立生效，与本协议闸门叠加而非替代。
- **剩余验证**：真机确认协议升版后确实停采、重新同意后 MQTT/定位/策略自动恢复。

### P0-3 个人信息保护影响评估（PIA）缺失（法定强制，未做）

- **法律依据**：PIPL 第 55 条——处理**敏感个人信息**、**不满十四周岁未成年人个人信息**、
  委托处理或向他人提供个人信息等情形，应事前进行个人信息保护影响评估；第 56 条要求报告与处理记录
  至少保存 **3 年**。
- **本产品触发点**：位置轨迹与环境音/截图属敏感个人信息；产品明确面向未成年人并设有
  "不满十四周岁监护人单独同意"入口；使用高德、微信支付两个第三方 SDK。
- **当前状态**：全仓无 PIA 报告或处理活动记录。
- **裁定**：上线前必须完成书面 PIA 并留存 3 年。评估要点见第五节。
  这不是"建议"，是法定动作；法务已提供模板结构，但**结论须由运营方据实填写并签署**，
  法务不代签、不预填"已取得同意"等事实性结论。

## 五、PIA 必查要点（供运营方据实填写，不得预填结论）

1. **处理活动描述**：收集类别（位置/应用用量/网址/图像声音/账号/设备）、目的、频次、数据流向（孩子端 → 服务端 → 家长端；官方托管 vs 自建）。
2. **第三方**：高德 SDK、微信支付 SDK 的名称、主体、收集字段、共享方式、合同或平台协议依据。
3. **合法性与必要性**：每类数据对应的监护功能目的；最小必要论证；为何不能用更温和数据替代（尤其环境音与实时画面）。
4. **未成年人专项**：监护人同意获取流程、不满十四周岁单独同意的实现与留痕、申报年龄非实名核验的残余风险及缓释措施。
5. **安全风险**：局域网 HTTP（自建）、管理后台越权访问、弱口令、文件上传、设备丢失、数据泄露与滥用场景。
6. **影响与措施**：对儿童隐私、人身安全的潜在影响；对应控制措施（权限模型、加密、保留期、审计、删除机制、访问控制）。
7. **结论与签署**：是否可接受剩余风险、责任人、日期、复核周期；报告与处理记录保存至少 3 年。

## 七、审核口径说明

- 本意见把"法律文本声称的事实"与"代码实际行为"作为同一审查对象；两者不一致即判缺陷，不以"代码功能已实现"替代"文本如实披露"。
- 未发现数据出境、自动化决策、广告画像、第三方统计/崩溃回传等情形；如未来引入，须重新评估并更新 PIA 与政策。
- 平台规则（软著、备案、年龄分级）属外部行政要求，法务只给出口径与清单，不代为取得。
