## 新增测试类与覆盖清单（65 例）

### `FileStorageServiceTest`（18 例）
- **落盘与文件名**：`storeDetailed` 的 `storedPath` 不含 `/`、`\`、绝对路径，且以净化名结尾；`ownerUserId`/`deviceId` 如实落库；`../../evil name?.png` → `evil_name_.png`（路径段/空格/问号全净化）、`C:\tmp\payload.bin` 只取末段；空名回落 `file`、全非法字符被替换；文件确实落在存储根内。
- **流式写入**：`size` 以真实写入字节数为准且磁盘内容 byte-for-byte 一致；跨 64KB 缓冲区的大流仍按真实长度落库；`InputStream` 中途抛 `IOException` 时**删除半截文件且 `save` 从未调用**。
- **URL / 解析**：未配 `baseUrl` 返回同源相对路径；配了 `baseUrl` 生成绝对地址并 `trimEnd('/')`；历史绝对路径 `storedPath` 归一化后仍可下载；带 `../../` 的 `storedPath` 绝不读到根外文件；记录存在但磁盘缺失 / 无记录均返回 `null`。
- **删除与读契约**：`deleteById` 用 `doAnswer` 断言「删记录时文件仍在」（先让下载 404，残留只是可清扫孤儿）、记录不存在返回 `false` 且不碰磁盘；`referencedFileNames` 读库失败**抛异常**而非返回空集，并把绝对路径归一化成文件名。

### `AppManageServiceTest`（21 例）
- **IDOR**：`installApp` 越权抛 `DEVICE_NOT_OWNED` 且**零指令下发、零台账落库**；`listApps` / 各写操作必过唯一归属校验；成功路径 `INSTALL_APP` payload 契约（`APK_URL`/`PACKAGE_NAME`/`VERSION_CODE`，缺省回落 `0L`）+ 预置台账。
- **授权意图红线**：新应用默认 `hidden=true` 且下发 `SET_APP_HIDDEN` + 只重建一次策略包；**设备上报 `hidden=false` 不得反向覆盖服务端意图且不得写库**（`saveAll` 调用数 0）；上报缺字段时 `appName` 保持「计算器」不退化成包名；卸载置 `installed=false` 且从不 `deleteAll`。
- **收敛与列表**：用本次真实台账调 `onInventoryInstalled`；`listApps` 非系统应用优先 + `appName` 大小写不敏感排序 + 策略合并 `blocked`/`dailyLimitMinutes`；`onlyInstalled=false` 走全量台账。
- **自身保护 / 批量语义**：`uninstallApp` 拒绝空包名 / 自身包名 / `.child` 后缀，**不产生任何指令记录**；`setAppHidden` 找不到应用抛 `PARAM_ERROR`、成功则立刻写回意图并重建策略包；`setAppsHiddenBatch` 过滤自身 + 去重 + 只重建一次、`all=true` 作用于全部已安装；`setAppLimit` 0→`null`；`setSuspendedBatch` 去重过滤并回写台账。

### `AdminAuditServiceTest`（14 例）
- `auditAreas` 由 `AREA_DEFS` 单向派生（含 `audit`，防前端硬编码漏项）且走 `audit:read` 闸门；无权限抛 `FORBIDDEN`。
- `auditPage`：默认上限 200 且分页下推 DB（captor 断言 `pageSize`）；`limit` 钳制 `[1,5000]` 含 0 / 负数 / 超大值；**未知领域返回空且两条查询都不调用**（绝不退化成不过滤）；领域过滤走 `findByActionInOrderByCreatedAtDesc` 且按请求 limit 下推；`truncated/total/maxRows` 如实回报；未登记动作归空领域、`result` 小写化；只为当前页 actor 补显示名且从不 `findAll()` 全表读家长。
- `alerts`：`ERROR/WARN/其他 → high/mid/low`；`RESOLVED|CLOSED → closed`、`ACKNOWLEDGED → acknowledged`、`ACTIVE → open`；只补当前批涉及的家长；`closeAlert` 告警不存在抛 `PARAM_ERROR` 且不写审计。

### `StorageMaintenanceServiceTest`（12 例）
- 闸门：无 `server:write` 抛 `FORBIDDEN` 且**清扫从未触发**；有权限时精确 `require("a1","server","write")`。
- 宽限期：`null → 7`、`0/-10 → 1`、`9999 → 365`、合法值原样透出（不接受「0 天立刻删全部」）。
- 审计：预演/执行文案分别含「预演/待删」与「执行/删除」；`dbReadFailed` 含「读库失败未删除」、`truncated` 含「已达单次上限」；动作与目标固定 `STORAGE_SWEEP` / `storage` / `uploads`（用 8 matcher `verify` 精确钉死）。
- 结果：`dbReadFailed`/`truncated`/`scanned`/`deleted`/`bytesFreed`/`samples` 如实透出。

## 踩坑闭环（新增 3 条铁律）

1. **泛型 `saveAll(any())` 在 Kotlin 里推不出类型变量**（NEW，本轮编译主因）：`JpaRepository.saveAll` 是 `<S : T> List<S> saveAll(Iterable<S>)`，裸 `any()` 报 `Not enough information to infer type variable S / T`（本轮 3 处）。修法：改用 `mockingDetails(mock).invocations.count { it.method.name == "saveAll" }` 按方法名计数，彻底绕开泛型 matcher（比 `ArgumentCaptor` / 显式类型 matcher 都稳）。
2. **`PageImpl` 会自动修正 `total`**（NEW）：Spring Data 在 `pageable.offset + pageSize > total` 时把 `totalElements` 改成 `offset + content.size`，于是 `truncated = total > limit` 恒为 `false`，断言假红。修法：桩里的 `PageRequest.of(0, pageSize)` 必须与被测 `limit` 同口径（`stubPage(..., pageSize = 1)`），别一律用默认 200。
3. **`store()` 返回访问 URL，不是文件名**（NEW）：`FileStorageService.store(...) = storeDetailed(...).url`，断言净化结果必须用 `storeDetailed().name`；同理 `StoredFile.url` 与 `StoredFile.name` 语义不同。

**既有铁律再次验证生效**：
- `CommandService.issueCommand(..., priority="HIGH")` 与 `AuditService.record(...)` 都是带默认参数的 Kotlin 方法，桩/verify 必须给满全部参数位 matcher（本轮 `issueCommand` 4 位、`record` 8 位：可空位 `isNull()`、非空 `result` 用 `anyString()`、`detail` 用 `ArgumentCaptor.capture()`），否则 matcher 与真实值混用。
- void/Unit 方法的闸门拒绝用 `doThrow(...).`when`(mock).require(...)`，不可 `when(...)`（轮 8 铁律）。
- 非空 `Collection` 参数 matcher 用 `(any(Collection::class.java) as? Collection<String>) ?: emptyList()`，避免 `any()` 返回 null 触发 Kotlin 非空检查（轮 9 铁律）。
- `Pageable` 非空参数用 `any(Pageable::class.java) ?: PageRequest.of(0, 1)`（轮 6 铁律）。

## 观察项（如实记录，本轮未改生产）

- **`AppManageService.SELF_PACKAGE` 缺口**：服务端硬编码 `"com.padguard.child"` + `endsWith(".child")`，**不匹配 debug 包名 `com.padguard.child.debug`**。孩子端 `CommandExecutor` 有第二道拦截且用 `BuildConfig.APPLICATION_ID`，故不是已确证的线上漏洞；但服务端注释自称「唯一指令入口，挡住能根本不产生指令记录」，对 debug 包这道闸是开的。测试按生产现状如实断言（只测明确会被拒的两个形态），未擅自改生产。是否收口为 `isOwnPackage` 式精确判定待拍板。
- **`resolve` 的穿越防护实际由「只取文件名」保证**：`File(meta.storedPath).name` 会剥掉任意 `../` 段，canonical 路径校验是纵深防御（防未来有人改成直接用 `storedPath` 拼路径）。本轮测试钉死了「带穿越片段时绝不读到根外文件」这一外部行为。
- 补测过程中**未发现需要改生产的真问题**：四个类的生产行为与注释契约一致，全部失败均为测试自身断言/桩的写法问题。
