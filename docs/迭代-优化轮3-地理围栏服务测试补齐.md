# 迭代优化轮 3 —— 地理围栏服务（GeofenceService）测试补齐

> 承接优化轮 2（统计接口加固）。本轮继续对**信任关键路径**做复审与门禁补齐。
> 通过测试清单盘点发现：`GeofenceService`（孩子安全区域进入/离开告警 + 围栏 CRUD 越权防护）**全仓零单测**，
> 而它直接关系到"孩子是否脱离安全区域"这类高信任告警，一旦回归改坏，家长端会静默漏警或误警。

## 二、改动位置（纯测试，未动生产代码）

新增 `padguard-server/src/test/kotlin/com/padguard/server/service/GeofenceServiceTest.kt`（9 例，全绿）：

1. **离开告警**：prev 在围栏内、本帧到 111km 外 → 仅 `GEOFENCE_EXIT`，不触发进入。
2. **进入告警**：prev 在外、本帧回圆心 → 仅 `GEOFENCE_ENTER`（`alertOnExit=false, alertOnEnter=true`）。
3. **开关全关**：`alertOnExit=false && alertOnEnter=false` → 跨越边界**零告警**（验证开关精确作用，杜绝刷屏）。
4. **禁用围栏**：`enabled=false` → 跳过，零告警。
5. **逐边界告警**：内→外→内（两开关皆开） → 恰好 `EXIT + ENTER` 各一次（`times(2)`），不重复刷屏。
6. **无围栏**：`findByDeviceId...` 返回空 → 零告警。
7. **updateZone 越权**：围栏属别的设备 → 抛 `BizException(code=GEOFENCE_NOT_FOUND=3003)`，不泄露归属、不 500。
8. **deleteZone 越权**：同上，且确认 `delete` 未被调用（`verify(never()).delete(any())`）。
9. **currentLocation 兜底**：无轨迹 → 回退到设备登记经纬度（31.23/121.47），不抛异常、不裸 0,0 误定位。

## 三、验证

- `:padguard-server:compileTestKotlin` 通过；`GeofenceServiceTest` **9/9 PASSED**。
- 路线纪律：Mockito 隔离仓储 + 真实 `LocationPoint`/`LocationTrack`/`GeofenceZone` 构造，**不加载 Spring 上下文**（规避全量集成 OOM）。
- **踩坑闭环（铁律复用并强化）**：Kotlin 非空参数 + Mockito 占位 matcher 不仅 `any()` 要补 `?: 默认`，
  **`eq(x)` 更要补 `?: x`** —— `eq(deviceId)` 返回 null 占位会触发 Kotlin 非空检查抛 `eq(...) must not be null`，
  并污染 Mockito 的 Matcher 栈，导致**同测试类其它用例级联报** `InvalidUseOfMatchersException` / `UnfinishedVerificationException`（误报在 `<init>` 第 32 行）。
  本轮统一改用 `eq(x) ?: x`、`any(Pageable::class.java) ?: PageRequest.of(0,1)`、`anyString()`（其返回类型本就非空安全），
  与 `StatisticsService` 测试既有范式一致并补强。该坑已记入本轮纪律，供后续 Kotlin+Mockito 测试复用。
