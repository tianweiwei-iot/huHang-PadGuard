## 三、验证

- `:padguard-server:compileTestKotlin` 通过；定向重跑四份测试类，**43/43 PASSED**（`tests="10"/"8"/"10"/"15" failures="0" errors="0"`，XML 已确认）。
- 路线纪律：Mockito 隔离全部依赖 + 真实实体构造（`Device`/`Command`/`CommandPacket`/`Policy`/`DeviceSetting` 等），**不加载 Spring 上下文**（规避全量集成 OOM，符合项目既有约 626 例集成测试跑不下的约束）。
- `afterCommit { block }` 在无 Spring 事务时**立即执行** block（不注册同步），故 `issueCommand`/`rebuildPolicy` 下游副作用直接落到 mock；`TraceIds.withNewTrace` 仅用 MDC；`PolicyVersions.allocate` 无事务时跳过行锁仅调 `nextVersion` —— 三者共同保证纯单元测试可走通。
- **踩坑闭环（铁律再次确认，本轮命中 R5/R6）**：
  - `apply` 块内 `this` 阴影：务必显式 `this@TestClass.field` 指向外层字段，避免自赋值造无主设备（轮 4 的 Ingest 已记，本轮 Unlock 复现）。
  - Kotlin 非空参数 + Mockito 占位：非空 `Map` 用 `any() ?: emptyMap()`（**不是** `anyMap() ?: emptyMap<String,Any?>()`，后者破坏 Matcher 栈；也**不是**裸 `any()`，对非空 Map 返回平台类型触发 NPE）；非空 String 用 `eq(x) ?: x`；`Pageable` 用 `any(Pageable::class.java) ?: PageRequest.of(0,1)`。缺 `?:` 必 NPE 并级联污染同测试类其余用例。
