## 三、复核后**排除**的疑似问题（避免误报）

- 家长端 `ServerPrefs.migrate()` 不会把内网 http 误升级成 https：只有 `Verdict.Rejected` 才尝试升级，内网 http 是 `Allowed(LAN_CLEARTEXT)`。
- 孩子端心跳路径 `/api/v1/device/heartbeat` 与服务端 `@RequestMapping("/api/v1/device")` 一致，baseUrl 不缺 `/api`；`RTC_WAKEUP` 仅存在于历史注释，实际全为 `ELAPSED_REALTIME_WAKEUP`。
- 看屏会话 `deadlineWallMs` 用裸墙钟是**既有有意例外**（跨重启落盘，只影响可用性与隐私、不参与管控判定），本轮不动，但隐私风险列入 U-02。
- `CommandType` / `KEY_*` / `FeatureKey` / `EVENT_TITLES`(22 项) / 家长与孩子错误码表 / MQTT topic / `/api/v1` vs `/v1` 前缀 / 43 个迁移的索引名（56 个无重复）与版本号（无冲突无乱序）逐项对照一致。
- 登录「用户不存在/密码错误」共用 1002、`usage_logs` 用 `received_at`、WS 读库异常放行、单副本部署、`ensureRebuilt` 对 ROLLBACK 行 return —— 均为已知有意设计。
- `admin123` 常量虽在 main 源码，但受 `demo-accounts-enabled` 门控 + 启动强制重置保护，不是裸奔后门；只列 U-10 提示运维脚本会误导排障。

## 七、第 20 轮（11-07 19:20–20:00）：把「加列漏迁移」变成会失败的测试

### 1. 新增机械守卫：`SchemaMigrationCoverageTest`（治本，防止第三次同类事故）

**问题**：生产档位 `ddl-auto=none` + Flyway，表结构**只**由迁移脚本创建；而 local/home 跑
`ddl-auto=update`，Hibernate 会自动补列。于是"实体加字段忘了写迁移"在开发环境完全看不出来，
上线打生产才炸 —— 这个坑已经踩过**两次**（`usage_sessions` 的 rest 列 → V2026110702；
`devices.entitlement_state` → V2026110703），症状都是 `column does not exist` 让整表读写 500。

**做法**：不去正则猜实体（`@Embedded`/隐式命名/`@Column(name=)` 三种来源猜不全），
而是让 Hibernate 按实体在内存库把表**真建出来**（`ddl-auto=create`），从
`information_schema` 读回物理表名/列名，与迁移脚本解析出的列集合对账；缺任何一列即失败，
失败信息直接列出 `表.列` 并给出修复指引。

**为什么可信**（不是"写了个永远绿的测试"）：
- 加了两道防空转断言（迁移表 ≥25、实体表 ≥20，解析器失效时先报错而不是静默通过）；
- 做了**变异验证**：把 V2026110703 内容清空重跑，测试立刻报出 `devices.entitlement_state` 缺失；
- 解析器按项目实际句式实现（`CREATE TABLE [IF NOT EXISTS]` / `ALTER TABLE ... ADD [COLUMN]`，
  一条 ALTER 支持多个 ADD，带引号的 `"key"` 按列名处理），新增 DDL 句式需同步实现而不是放宽断言。

### 2. U-11：图标换新后删除旧文件（`AppManageService`）

孩子端每 30 分钟全量上报，图标内容一变（换主题、应用升级、深色模式）就新增一个 PNG +
一条 `uploaded_files` 记录，旧文件从不删除，一台设备上百个应用长期累积。

改为：**先落库、后删文件**。顺序反了的话，一旦 `saveAll` 抛异常，库里仍指向旧图标而文件已删，
两端一片空白图标且**永不重建**（下次上报 hash 未变 → `iconUpdate` 返回 null，不会重新落盘）；
按现在的顺序最坏只留一个无人引用的孤儿文件，由磁盘孤儿清扫兜底。

### 3. 顺带发现并修复：保留期清理会删掉**正在使用**的图标（P1，L-19 的副作用）

L-19 修"图标归属"时给图标文件补上了 `device_id`，于是它落进了
`findDeviceFilesCreatedBefore`（"设备上传且超过 90 天即删"）的范围。但图标与截图/录屏不同：
**它没有生命周期终点** —— 应用一直装着，图标就要一直在。一旦被删：
`installed_apps.icon_url` 指向 404，且因为 hash 没变**永远不会重新落盘**，
家长端从此一片空白图标（装得越久越明显）。

修复：`cleanupOrphanDeviceFiles` 先从 `installed_apps.icon_url` 取"在用图标 id 集合"并排除；
**读库失败时整轮跳过、一个都不删**（与离线队列 `readOrNull()==null` 同一约定：
不能把"读不出来"当成"没有图标"，否则一次数据库抖动就会删光所有在用图标）。

### 4. `/v1/auth/register` 补频控

注册是唯一"匿名 + 写库"的入口，之前**完全没有频控**：一次脚本就能批量建号（每个号还白送一份
试用订阅台账），也是手机号枚举的放大器（"已注册"与"格式不对"两种回包即可判定）。
新增 `register` 场景：默认 **3 次/分钟，仅 IP 维度**（账号维度对注册没有意义）。
频控放在建号之前，被限流时库里不留半成品账号。

**副作用与处理**：集成测试每个用例都会开一个家长账号，改完立刻有 5 个用例变 429。
已在 6 个会建号的集成测试类里显式放开该阈值（`padguard.ratelimit.register=200/1000`），
并注明"频控行为由 `RateLimitTest` 单测覆盖"——测试不该被生产频控误伤，也不该靠它来验证。
