## 二、改动位置（全部服务端，未改任何前端契约）

1. **`padguard-server/src/main/kotlin/com/padguard/server/service/StatisticsService.kt`**
   - 新增常量 `companion object` 内 `const val APP_USAGE_HISTORY_MAX = 500`（注释说明取值依据：月视图约每天 16 次余量）。
   - `appUsageHistory` 末尾由 `return result.sortedByDescending { ... }` 改为
     `return result.sortedByDescending { ... }.take(APP_USAGE_HISTORY_MAX)`。
   - **语义保持**：先按时间倒序、再取最近 N 条；客户端原本期望"全部"，截断到最近 500 条是严格更优（渲染更快、报文更小），且不破坏既有的倒序/字段契约。
   - 该修复**不触碰** `readLogs` 的分页流式读取（内存折叠仍按 2000/页），仅限制最终返回规模。

2. **`padguard-server/src/test/kotlin/com/padguard/server/service/StatisticsServiceCoverageTest.kt`**（NEW）
   - `appUsageHistory_capsResultAtMax`：构造 600 条同应用记录 → 断言返回 500 条、倒序首条为最晚一次、整体倒序、末条为被截断窗口内最旧一次（更早的已丢弃）。
   - `today_reportsAggregatedMinutesAndDate`：`USAGE_TOTAL` 3600s → 断言 `totalUsageMinutes=60`、date 为服务端今日、无应用榜单。
   - `usage_buildsDailySeriesAndCounts`：单日 `USAGE_TOTAL` 600s + 2 事件 + 3 告警 → 断言总量 10 分钟、逐日 1 条且当天 10 分钟、违规 2、告警 3。
