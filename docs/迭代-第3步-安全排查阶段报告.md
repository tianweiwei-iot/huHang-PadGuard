## 二、修复计划与改动位置

### 2.1 F-01：refresh token 单会话吊销 + 轮换（核心修复）

**根因**：JWT 无状态，服务端没有令牌清单可比对；旧实现仅靠 `users.token_version` 整账号吊销，无法「只吊销某一台设备」，refresh token 泄漏即等于长期可用。

**方案选型（两套）**：

| 维度 | 方案 A：纯整账号吊销（旧） | 方案 B：会话表 + jti 轮换（本期采用） |
|---|---|---|
| 状态存储 | 无 | `user_sessions` 表（每设备一条） |
| 单设备吊销 | 不支持 | 支持（`revokeSession`） |
| 重放防护 | 无（令牌永不变） | 每次 refresh 轮换 jti，旧 token 立即失效 |
| 复杂度/故障面 | 最小 | 多一张表 + 写入，但写入失败不阻断登录（best-effort 兜底） |
| 兜底 | — | 保留 `token_version` 整账号吊销作为最后防线 |

**改动位置**：
- **迁移** `src/main/resources/db/migration/V2026110902__refresh_token_sessions.sql`：新建 `user_sessions`（id/user_id/device_label/refresh_jti/created_at/last_refreshed_at/revoked/revoked_at）+ 索引（含 `refresh_jti` 唯一索引）。全 `IF NOT EXISTS`，H2(MODE=PostgreSQL) 与 PG16 双兼容。
- **实体** `domain/ExtraModels.kt`：新增 `UserSession`。
- **仓储** `repository/Repositories.kt`：新增 `UserSessionRepository`（`findByUserIdAndRevokedFalse` / `findByRefreshJtiAndRevokedFalse` / `findByUserIdAndIdAndRevokedFalse` / `countByUserIdAndRevokedFalse` / `revokeAllForUser`）。`revokeAllForUser` 为 `@Modifying(flushAutomatically=true, clearAutomatically=true)` 条件 UPDATE（只碰 `revoked` 标记，不覆盖并发写入其他列 —— 遵守本仓库「条件 UPDATE 必须双自动」不变量）。
- **令牌** `security/JwtTokenProvider.kt`：`createRefreshToken` 写入 `jti` 声明；`parseUserToken` 回读 `jti`；`UserTokenPayload` 增加 `jti` 字段。
- **逻辑** `service/AuthService.kt`：
  - `issueSessionTokens(user)`：登录即建一条 `user_sessions`（携带随机 jti）；session 写入失败 best-effort 不阻断登录。
  - `refresh`：解析 jti → 查 `user_sessions` 未吊销记录 → **轮换 jti**（旧 refresh token 立即失效，防重放/防多端共用同一令牌）→ 返回新令牌；jti 缺失/不匹配/已吊销一律拒续期。
  - `logout` / `changePassword` / `revokeAllSessions`：在 `token_version +1` 之外，额外 `revokeAllForUser` 吊销全部 refresh 会话，并 `revokeUser` 掐断 WS 长连接。
  - `listSessions(userId)`：列出未吊销会话（脱敏 DTO，不外泄 jti/userId/revoked）。
  - `revokeSession(userId, sessionId)`：仅置位该会话 `revoked`，不影响其他设备；按 `findByUserIdAndIdAndRevokedFalse` 强制归属校验（防 IDOR）。
- **DTO** `dto/SessionDtos.kt`：新增 `UserSessionView`（id/deviceLabel/createdAt/lastRefreshedAt，不含敏感字段）。
- **控制器** `controller/ParentControllers.kt`（`AuthController`）：
  - `GET /v1/auth/sessions` → `listSessions`（已登录只读）。
  - `DELETE /v1/auth/sessions/{sessionId}` → `revokeSession`（已登录写操作，轻量频控 `revoke_session`）。
  - 两端点均落在 `/v1/**` 且不在放行清单，必须经 `ParentAuthInterceptor` 携带家长 JWT，`userId` 取自令牌而非请求体。

### 2.2 F-02：CORS 通配源复核

`WebConfig.addCorsMappings` 用 `allowedOriginPatterns("*")` + `allowCredentials(false)`。
- **为何可接受**：认证模型是 **Bearer Token（OkHttp 头，不依赖 Cookie）**，原生 App 与同源后台 SPA 均不使用凭据型跨域；显式 `allowCredentials(false)` 已消除「通配源 + 凭据」这个被浏览器禁止且危险的组合。
- **残留风险**：通配源意味着任意网站可在用户已登录态下用 JS 发起请求（无凭据则拿不到 Cookie，但能带 Bearer 头若用户自行粘贴）。本产品是受控原生 App + 同源后台，无第三方网页嵌入场景，风险可忽略。如需进一步收紧，上线前可改为显式白名单（运营后台域名 + 受控 App scheme），列为可选增强。

### 2.3 F-03：SQL 注入核查（无向量）

全量 `@Query` 均为 JPQL 参数化（`@Param` / 命名参数），派生查询（findByXxx）由框架生成参数化 SQL。
- 唯一使用字符串插值的点：`ParentErasureDao.residualReferences` 的 `jdbc.queryForObject("select count(*) from $table where $column = ?", userId)` —— `$table`/`$column` 来自代码内常量白名单 `ParentErasurePlan.USER_FK_COLUMNS`，**非用户输入**；`userId` 为 `?` 绑定参数。
- `ParentErasureDao.erase` 的 `step.sql` 同样来自内部常量表，参数全部 `setParameter` 绑定。
- 结论：**无 SQL 注入面**；插值处依赖代码级白名单，需在重构时保持「表名/列名不得取自外部」的纪律。

### 2.4 F-04：XSS 核查（低风险，职责在端）

服务端统一以 `ApiResponse{ code,message,data,timestamp }` 返回 **JSON**；异常经全局 `ControllerAdvice` 归一为 JSON `message`，**不反射原始用户输入进 HTML 响应体**（校验失败文案为受控中文，不含请求体回显）。
- 存储型 XSS：审计/设备名/备注等用户文本以 JSON 透传给 SPA，**渲染转义由前端框架负责**（受控原生 WebView/SPA 默认转义）。服务端侧已确保不输出 HTML 文档、不 eval 任何字段。
- 结论：服务端无 XSS 注入点；上线前由端侧安全检查（WebView 配置 `setJavaScriptEnabled` 审计、富文本渲染转义）收尾。

### 2.5 F-05：IDOR 越权核查（已闭环）

- **audit-logs**：`ParentComplianceController.auditLogs` 取 `@RequestAttribute("userId")` → `AuditService.query`，当 `deviceId` 非空时经 `ownershipGuard.requireOwned(userId, deviceId)` 归属校验；无 deviceId 时按 userId 收窄。越权读被挡。
- **新增会话端点**：`listSessions`/`revokeSession` 一律用令牌中的 `userId`，`revokeSession` 再经 `findByUserIdAndIdAndRevokedFalse(userId, sessionId)` 双重过滤 —— 即使传入他人 sessionId 也查不到，返回「会话不存在」。**跨账号吊销不可达**。
- **其他带 deviceId 端点**（`/policies/{deviceId}/...`、`/devices/{deviceId}/agreement` 等）均由 Service 层 `ownershipGuard` 校验归属，统一复用现有守卫，未引入新越权面。

## 三、测试（新增，全绿）

- `AuthServiceSessionTest.kt`（5 例）：登录建会话 + refresh 轮换 jti 且旧令牌失效；重放已轮换令牌被拒；单设备 revoke 只废那台且新登录可用；全局 logout 废全部会话；listSessions 只回未吊销且不含敏感字段。
