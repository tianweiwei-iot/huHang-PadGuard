## 一、需求与根因回顾

### 1.1 需求 1：自启动守护未生效

| 现场现象 | 根因 | 本次对策 |
|---|---|---|
| 孩子端 UI 出现在「最近任务」，划掉后守护不自动重启 | ① `MainActivity` 未声明 `excludeFromRecents`；② 划任务=杀进程时，进程内自愈（`onTaskRemoved` 延迟重启、START_STICKY、动态广播）全部随进程死亡；外部仅剩 JobScheduler 看门狗单点，Android 12+ 上从 Job 回调启动 FGS 还可能被系统拒绝（原代码仅记日志降级） | ① Manifest 加 `excludeFromRecents`；② 新增**双进程守护**（`:daemon` 进程文件心跳互拉）+ **AlarmManager 第二条系统调度通道**，与既有看门狗形成四层保活 |
| 屏幕监控授权随进程死亡消失，需手动重授 | MediaProjection 令牌是进程内 IBinder，平台隐私红线决定其**无法持久化**（Device Owner 也无静默接口）——这不是实现缺陷，是平台边界 | 不试图"保存令牌"：看屏改走无障碍通道（持久授权，零弹窗）+ **进程重启后主动恢复推流**（`live_view_state` 窗口文件），服务端 `reconcileLiveSessions` 8s 冷却重发作第二保险 |

### 1.2 需求 2：悬浮框重设计

原「悬浮状态卡」（两行文字）无进度可视化、不能拖拽，且延时申请入口只存在于孩子端 App 内 Compose 浮层——绑定后图标已隐藏，孩子平时根本触达不到。本次以**玻璃球**替代，延时申请复用既有三端审批工单流（服务端 `UsageDelayService`，零服务端改动）。

## 二、改动清单（孩子端 app 模块）

### 2.1 守护保活（新增 3 文件，改 4 文件）

| 文件 | 性质 | 改动 |
|---|---|---|
| `service/GuardHeartbeat.kt` | 新增 | 跨进程安全的**文件心跳与状态原语**：`guard_alive`/`daemon_alive` 心跳（单调时钟判定，免疫改时间与重启）、`guard_state` 绑定态、`live_view_state` 看屏恢复窗口；原子写（tmp+rename），不用 SharedPreferences（其实例按进程缓存，跨进程读必陈旧） |
| `service/GuardDaemonService.kt` | 新增 | **双进程守护**（`android:process=":daemon"`）：极轻（无 Hilt/无数据库），5s 一轮检查主进程心跳，陈旧且已绑定 → 拉起 GuardService（20s 防重试间隔）；未绑定 → 自停。API 31+ 自提为 dataSync 前台服务拿"后台启动 FGS"豁免身份，API <31 为普通 Service（当年无此限制） || `receiver/GuardAlarmReceiver.kt` | 新增 | **闹钟兜底通道**：60s `setWindow` 非精确闹钟（系统可批处理更省电），检查双方心跳缺谁拉谁，已绑定才自续期、未绑定取消排班 |
| `service/GuardWatchdogService.kt` | 改 | 看门狗同时守护 GuardService 与 daemon；顺带排闹钟通道 |
| `service/GuardService.kt` | 改 | ① 主循环每轮写心跳 + 检查 daemon 存活互拉；② `observeBinding` 持久化绑定态并排/销闹钟；③ `onCreate` 启动 daemon；④ 新增 `resumeLiveViewIfActive()`：进程重启后看屏窗口有效即主动恢复推流；⑤ `StartLiveView/StopLiveView/解绑` 写/清 `live_view_state`；⑥ 新增 `REASON_DAEMON/REASON_ALARM` |
| `receiver/BootReceiver.kt` | 改 | 开机/覆盖安装/USER_PRESENT 时一并拉起 daemon、按绑定态排闹钟 |
| `AndroidManifest.xml` | 改 | 注册 daemon service（`:daemon` + dataSync）、GuardAlarmReceiver；`MainActivity` 加 `excludeFromRecents="true"`；注册 GlassBallDialogActivity |

**四层保活总览**（任一失效其余仍能恢复）：

```
① onTaskRemoved 秒级重启（进程尚在）     ② START_STICKY（系统尽力）
③ :daemon 双进程心跳互拉（最坏 ~40s）    ④ JobScheduler 看门狗 60~90s
⑤ AlarmManager 闹钟 60s                  ⑥ BootReceiver（开机）
```

> **同期互补修复（另一会话落地，已包含在最终 APK 中）**：
> ① `AndroidManifest.xml` 的 `GuardDaemonService` 补配 `android:process=":daemon"`（漏配则该服务实际跑在主进程内，"双进程互保"是空壳——主进程被杀时守护一并死亡，这是本机制生效的硬前提；已用 aapt2 从最终 APK 二进制清单核验 `:daemon` 在位）；
> ② `GuardService.bootstrap()` 在授权复检后补跑 `healRuntimePermissions()` + `recheckSpecialCapabilities()`，使 DO 设备的运行期权限静默自愈在每次（重）启动后零等待生效。

## 三、三端时间同步链路（本次不改动，仅核对）

```
孩子双击玻璃球 → 选档提交 → POST /usage/session/delay/request
   → 服务端 UsageDelayService.request：仅落 PENDING 工单（单设备单 PENDING + 单日≤120 校验）+ WS 通知家长
   → 家长端：消息中心铃铛红点 + 全局弹窗 / 时间管控页内联审批（既有）
   → 家长「同意」→ session.extendedMinutes += minutes + WS 通知家长端刷新
   → 孩子端 15s 会话轮询带回新 extendedMinutes → liveRemainingMs 立即变大
   → 玻璃球剩余数字秒级更新；PolicyEngine.tick 的 DAILY_LIMIT 同步解除
```

- 权威锚点：服务端 `startEpoch + serverNow`；孩子端只做本地插值；改本地时间不漂移。
- 防绕过三保险：孩子端待审只读 + 服务端单 PENDING + 单日上限（既有，未动）。

### 4.2 真机实测（华为 AGS6-W10 / Android 10，20261020 旧包）

> 20261021 新包因 EMUI 家长控制（孩子模式）对"PC 工具"来源安装强制索要**机主华为账号密码**，自动化安装被系统级拦截、无法代输凭证（见 4.3）。以下结论基于 20261020 旧包实测 + 新包代码复核。

**已确认的事实与根因：**
- ✅ **玻璃球正常渲染**：设备截图可见"已用 XX 分 / 剩余 mm:ss"三行布局清晰，秒级刷新正常（旧包已含此能力）。
- ✅ **守护不自动重启的真因定位**：`am kill` 整包击杀后，EMUI `iaware/trustsbase` 分类拦截 daemon 的**普通服务启动**（`Service starting has been prevented by iaware or trustsbase ... GuardDaemonService`，无异常无回调）—— 这正解释了用户现场"守护不自动重启"。主守护走 `startForegroundService` 路径从任何上下文都能起，唯独 daemon 的普通服务路径被拦。
- ✅ **EMUI 杀应用会一并清除系统调度**：JobScheduler 看门狗任务、AlarmManager 闹钟均被清掉，应用整夜无人拉起（验证时设备已 21h 未重启、进程全无、心跳停在昨晚 18:24）。
- 🐞 **玻璃球拖拽瞬移**：首次移动以 0 为基准累加 → 球瞬移（20261021 已改为传增量修复）。
- 🐞 **单击/双击均不响应**：`GestureDetector` 同时覆写 `onDoubleTap` 时 `onSingleTapConfirmed` 不再派发（Android 已知怪癖），且双击依赖进程间隔不可靠（20261021 已改为手写点击/双击判定修复）。

## 五、边界与风险（如实声明）

- **强制停止不可绕**：设备被「设置 → 强制停止」进入系统停止态后，双进程/看门狗/闹钟/广播全部失效——Android 安全模型，应用层无解；唯一正解是 Device Owner（`SecurityEnforcer.DISALLOW_APPS_CONTROL` 置灰停止按钮）。
- **MediaProjection 令牌边界**：进程死即失效、不可持久化（平台红线）。本方案以"无障碍通道为主 + 看屏会话主动恢复 + 按需通知引导"应对；录屏类确需投影时仍保留一次用户确认。
- **闹钟通道在 Android 12+**：闹钟唤醒非 FGS 启动豁免上下文，直接拉 GuardService 可能被系统拒绝（失败仅记日志）；该层主要覆盖 Android 11 及以下与宽松 ROM，12+ 由双进程 + 看门狗兜底。
- **ROM 差异**：激进省电 ROM 仍可能延迟投递系统调度；四层保活保证"最终一定恢复"，最坏恢复时间约 1~2 分钟量级。
- **玻璃球单击 = 家长验证入口**（保留原悬浮卡能力）；双击 = 延时申请。孩子误触单击会看到密码框，属既有产品行为，未改。
