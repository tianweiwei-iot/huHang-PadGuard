## 1. 为什么会「退不出、也解锁不了」

**不是守护被杀，不是服务端挂了，也不是家长端解锁功能坏——是孩子端连不上服务端。**

平板 logcat（12:10~12:11）里 `GuardService` / `PolicyEngine` / 看门狗 / 闹钟全都在持续运行（PID 12077），但刷屏：

```
OkHttp: <-- HTTP FAILED: java.net.ConnectException: Failed to connect to /192.168.1.12:8090
commands: network failure: Failed to connect to /192.168.1.12:8090
GuardService: connectivity=false, mode=POLLING
```

电脑有**双网卡**，服务端监听 `0.0.0.0:8090`（两个地址都能服务），但两台设备各自只能到达其中一个：

| 设备 | `192.168.1.11`（以太网） | `192.168.1.12`（WLAN） |
|---|---|---|
| 家长端 `192.168.1.10` | ❌ 100% 丢包 | ✅ 通（当前配置，别改） |
| 孩子端 `192.168.1.14` | ✅ 0% 丢包 / 4.5ms | ❌ `Destination Host Unreachable`（当前配置，错的） |

孩子端 `padguard_child_transport.xml` 里存的是 `http://192.168.1.12:8090/api/v1/`，于是心跳、指令长轮询、家长端下发的解锁/暂停管控指令**全部发不出去**（服务端今日 `/api/v1/device/*` 为 0 条）。本地只能按落盘快照继续判定：

```
usage_session_snapshot.xml: day=2026-11-09, remaining_ms=0, active=true, quota_minutes=120
```

→ 每 tick 重新派生 `DAILY_LIMIT` → 锁屏页持续显示「使用时间已用完」且没有可用的解锁出口。**远程解锁不是点了没用，是根本送不到。**

补充：日志里 MQTT 连 `192.168.1.100:1883` 报 `EHOSTUNREACH`，那是 debug 构建期探测不到本机 IP 时的**占位默认值**（`app/build.gradle.kts` 的 `debugFallbackMqtt`），不是配置被改坏。服务端 local 档启动参数带 `--padguard.mqtt.enabled=false`，孩子端会退化为 HTTP 轮询，功能不缺、只少了实时推送的毫秒级延迟。

## 2. 立即可用：临时退出锁屏（应急窗口，不是解锁）

**前提**：平板 USB 调试已开启、电脑有 adb（本机路径 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`）。

```bash
adb devices                                  # 应看到 3ZPBB24B20206385（孩子端）
adb -s 3ZPBB24B20206385 shell am force-stop com.padguard.child.debug
```

- 效果：锁屏 Activity 立刻消失，回到桌面（本次已验证有效）。
- **限制（务必知道）**：守护服务有 `START_STICKY` + 看门狗 / 闹钟，约 30 秒内会被拉回，本地策略仍会重挂 `DAILY_LIMIT`，锁屏页可能再出现。它只是给你一个操作窗口，**不等于解锁**。
- 装的是 release 包时包名是 `com.padguard.child`（无 `.debug`），命令需相应替换。
- 没有电脑时：可尝试华为平板的**安全模式**（长按电源菜单中的「关机」选项，部分 EMUI 版本会提示进入安全模式）临时禁用第三方应用，处理完重启退出；进入路径随 EMUI 版本而异。

**真正解锁只有一条路**：让孩子端重新连上服务端，再由家长端下发解锁 / 关闭时间管控 / 追加额度。

## 3. 恢复管控：重装 + 重新绑定（照做）

### 3.1 准备安装包

用本轮构建的修复包：

```
D:/builds/padguard/app/outputs/apk/debug/app-debug.apk
```

44.5 MB，包名 `com.padguard.child.debug`，与设备原包签名一致，包含第 6 节的五处代码修复（①②③④⑤）。

> ⚠️ **必须手填地址，别指望构建期默认值。**
> 真正决定默认接入点的是 `core/transport` 模块的 `BuildConfig` —— debug 档在
> `core/transport/build.gradle.kts` 里写死 `http://192.168.1.100:8090/api/v1/`；
> `app` 模块的 `-PBASE_URL` / `-PMQTT_BROKER` 注入**不影响** `TransportSettings`。
> 实测：给 app 注入 `.11` 后重新构建，APK 里 `TransportSettings` 读到的默认仍是 `.100`
> （两个 apk 的 md5 完全一致）。这也正是旧包日志里 `192.168.1.100:1883` 的来源。
> 所以**无论装哪个包，都要做 3.4 的手填 + 连接测试**，没有捷径。

### 3.2 先确认服务活着（在电脑上）

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.11:8090/v1/devices
```

返回 `401` 即正常（`401` = 没带令牌，恰恰说明服务在响应）。`000` / 连接超时才需要查服务端。

### 3.3 安装

```bash
adb -s 3ZPBB24B20206385 install -r "D:/builds/padguard/app/outputs/apk/debug/app-debug.apk"
```

华为 EMUI 可能在平板上弹安装确认，需要在平板上点「继续安装 / 允许」（这也是当初记录里「装包需解锁 + 人工确认」的原因）。若提示签名冲突，先卸载残留再装。

### 3.4 绑定页填地址并自检（**最关键一步**）

打开「护航成长」→ 绑定页 → 服务器设置：

```
http://192.168.1.11:8090/api/v1/
```

- 只填 `http://192.168.1.11:8090` 也可以，`EndpointSafety.check()` 会自动补 `/api/v1/` 前缀。
- **不要填 `.12`**；**也不要动家长端**，家长端继续用 `.12`。
- 点「连接测试 / 自检」（会打免鉴权的 `/api/v1/device/time`），必须显示 **「连接正常：http://192.168.1.11:8090/api/v1/」** 才继续绑定。
- 也可以用平板浏览器访问 `http://192.168.1.11:8090/api/v1/device/time`，能返回服务端时间即通。

### 3.5 重新绑定

在家长端获取绑定码 / 扫码完成绑定。若提示「设备已存在」或设备数超限，先在家长端解绑或删除旧设备记录（服务端仍记着 `c7d3cbea-...` 且状态 OFFLINE）；找不到入口可以让我从服务端处理。

> 服务端绑定响应里的 `baseUrl` / `mqttBroker` 默认为空，**不会覆盖**你手工填的地址（`BindResult` 契约 V1.1，仅非空才下发）。

### 3.6 授权向导与首次使用

- 装机引导版本 `CONSENT_VERSION_CURRENT=2` 会重新走一遍；目标机 EMUI10 / API29 **适用 7 项**（无「精确闹钟」，该项需 API31+）。重点确认：电池优化白名单、厂商自启动 / 后台弹出界面、通知。
- 跨日按 A13「每日计时 = 孩子确认制」会进**待确认等待页**，需孩子点「开始计时」才起表（未确认永不开始，这是设计不是故障）。若希望装完立即可用，先在家长端设置今日额度或关闭时间管控。

## 5. 防复发：网络侧根治建议

1. **给电脑以太网网卡设固定 IP `192.168.1.11`**（或在路由器做 DHCP 静态分配）。DHCP 续租换 IP 会让所有客户端接入点同时失效，这是最容易复发的点。
2. **在路由器关闭「AP 隔离 / 客户端隔离 / 无线隔离」**，让 `.10` 和 `.14` 都能访问两个地址，之后才谈得上统一接入点。当前状态下强行统一只会把一台设备也弄离线。
3. 换网络 / 换 IP 后：孩子端在绑定页改地址并自检；家长端对应改自己的地址。
4. MQTT：当前没有 broker（local 档已禁用），孩子端会快速失败并退化为 HTTP 轮询，属预期。日后启用 broker 时，地址必须指向可达 IP，别留 `.100` 占位。
5. 排查习惯：服务端 `0` 条孩子端请求 **≠** 孩子端进程死了，也可能是「发不出去」。判断顺序应是：平板侧 `ping` 服务端 IP → 平板 logcat 看 `ConnectException` → 再看服务端 access log。
6. **构建侧已改（本轮修复 ⑤）**：`core/transport` 的 debug 默认接入点现已读 `-PBASE_URL` / `-PMQTT_BROKER`（未注入回退 `.100`，保持原行为），`TransportSettings` 读的就是它，所以注入终于能落到运行时默认，重装不再强制手填。release 档不受影响（仍是 `example.com`）。按约定未提交 git。

## 6. 本轮已修的代码缺陷（已包含在上述安装包，未提交 git）

> ①② 是排查中发现的真实缺陷，但**不是这次离线/卡死的主因**（主因是第 1 节的网络地址不可达）。
> ③④⑤ 是后续「全面优化完善」中把「掉线 → 锁屏跨日 → 无法解锁 → 无法开次日计时」闭环做健壮时补的加固。

| # | 缺陷 | 修复 |
|---|---|---|
| ① | 隐藏形态下 `MainActivity` 会 `finish()`，系统杀进程后重建的是 `LockScreenActivity`，而它和 `Application.onCreate` 都不启动守护；后台 Receiver / Job / Alarm 在国产 ROM 清通道或后台启动 FGS 受限时会集体静默失败 | `PadGuardApplication.ensureGuardAfterProcessRestart()`（绑定态文件标记 + 主进程守卫）、`LockScreenActivity.onCreate` 前台补拉、`GuardService.REASON_PROCESS_RESTART` 空分支 |
| ② | 锁屏页 `isAwaitingStartState` / `isEyeCareState` 只在 `onCreate` 取一次快照，跨日 `DAILY_LIMIT → AWAITING_START` 后页面仍显示旧文案且不出现「开始计时」按钮，按 A13 会永久卡住 | `lockController.state.collect` 实时同步两个 Compose 标记 |
| ③ | 联网恢复时只 `uploadPending()`，锁屏/会话要等下一轮 tick（最长 15s）才对账：服务端已解锁/改策略/跨日已被家长起表 → 锁屏滞后收起；离线本地起表（`pendingStartSync`）也延迟补发，家长端看不到今日计时起点 | `GuardService.observeDownlink` 的 `ConnectivityChanged` 在线分支**同时** `refreshPolicy()` + `usageSessionManager.refresh()`（异步 `scope.launch`，不阻塞下行采集）；`refresh` 内置补发通道把离线起表即时同步给服务端 |
| ④ | 锁屏页 `detailState`（通用副文案，如「使用时间已用完」）只在 `onCreate` 取一次：跨日 `DAILY_LIMIT → AWAITING_START` 后标题已变「今日使用计时尚未开始」，下方却挂着过期旧副文案，造成困惑 | `lockController.state.collect` 在 `AWAITING_START` / `EYE_CARE` 专属主题下清空 `detailState`，固定文案交由 `LockScreenContent` 渲染 |
| ⑤ | 构建期 `-PBASE_URL` / `-PMQTT_BROKER` 只注入 `app` 模块 `BuildConfig`，而 `TransportSettings` 读的是 `core:transport` 的 `BuildConfig`（debug 写死 `.100`）→ 注入对所有重装包无效，必须每次手填 | `core/transport/build.gradle.kts` 的 debug 档也读 `-PBASE_URL` / `-PMQTT_BROKER`（未注入回退 `.100`，保持原行为）；现在 `./gradlew :app:assembleDebug -PBASE_URL=http://192.168.1.11:8090/api/v1/` 会让运行时默认接入点真正变成 `.11`（release 不受影响） |
| ⑥ | 重连瞬间只回拉策略/会话，**没主动兜底拉命令**：离线期间家长下发的 `UNLOCK` / `START_TIMER_CONFIRM` 只能等 `startCommandLoop` 下一跳（≤3s）或心跳提示（≤30s）才补到，表现为「家长点了解锁 / 已开始计时，孩子端却没反应」——正是「无法解锁 / 无法开次日计时」的最后一公里 | `ConnectivityChanged` 在线分支新增 `drainPendingCommands()`（异步 `scope.launch`）：联网瞬间把漏推的一次性指令立刻补拉并执行；心跳/轮询通道照常保留，不冲突 |
| ⑦ | 锁屏页 `onResume` 不评估日切：孩子次日亮屏时，会话重置要等下一轮 Guard tick（≤15s），期间锁屏页停在昨天的 `DAILY_LIMIT` 旧文案（虽最终会翻，但醒屏瞬间仍像「卡在旧锁屏」） | `LockScreenActivity.onResume` 主动 `usageSessionManager.checkDayRollover()`（幂等，`runCatching` 兜底）：醒屏即把昨天的耗尽快照重置为「今日待确认」，下一轮 `syncAutoReasons` 立刻挂 `AWAITING_START` 并给出「开始计时」按钮 |

**如实说明**：③④⑤⑥⑦ 是「全面优化完善」新增加固，不改变第 1 节离线主因的结论。门禁实测：`:app:testDebugUnitTest --rerun-tasks` **215 例 / 0 失败 / 0 错误**（含本轮新增的 `锁屏页 onResume 必须主动评估日切`、扩展的 `联网恢复必须主动回拉策略与会话` 覆盖 `drainPendingCommands`）；`:app:assembleDebug` + `:app:lintDebug` **BUILD SUCCESSFUL，0 Error / 78 Warning**（历史 Deprecated 告警）。配套契约测试 `GuardRestartContractTest.kt` 现已 13 例。

## 7. 常见误判

| 现象 | 真相 |
|---|---|
| `padguard-server/server-run.log` 停在昨晚 20:05 | 进程一直活着、access log 持续在写；是 stdout 落盘问题，**别用它判断服务存活** |
| 服务端今天没有孩子端请求 | 本次是**请求发不到服务端**，不是端侧没发（logcat 有 `ConnectException`） |
| 家长端显示「离线」 | 读的是 `/v1/devices` 里孩子端设备的 `online` 字段，家长端自身通信全程 200 |
| 家长端点「解锁」没反应 | 指令排在服务端等孩子端长轮询来取；孩子端连不上就永远取不到 |
