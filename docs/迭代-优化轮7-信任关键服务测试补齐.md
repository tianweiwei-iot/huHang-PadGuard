## 3. 踩坑闭环（本轮新铁律，已记入纪律）
- **`JavaMailSender.send` 双重载歧义 + `MimeMessage` 无无参构造**：
  `send` 同时存在 `send(MimeMessage)` 与 `send(vararg MimeMessage!)`，Kotlin 用 matcher 调 `send` 会编译期重载歧义；且 `MimeMessage()` 无无参构造（只有 `MimeMessage(Session)` 等）。
  → 不直验 `send`（歧义且无法稳定匹配生产侧单参调用），改为直验**唯一无歧义**的 `createMimeMessage()`——它仅在下发路径（try 块内、send 之前）被调用一次，足以证明是否进入发送分支；桩返回用真实 `MimeMessage(Session.getDefaultInstance(Properties()))`；异常吞测试改打在 `createMimeMessage` 上，验证整段 `try/catch` 兜底（与打在 send 上等价，都落在同一 catch）。
- **非空参数 matcher 缺 `?:` 必 NPE 并污染 Matcher 栈（级联失败）**：
  `listMessages` 的 `verify(...).findByDeviceIdOrderByPublishedAtDesc(eq("d1") ?: "d1", captor.capture())` 中 `captor.capture()` 对**非空** `Pageable` 参数返回 null 占位 → Kotlin 空检查在调用点抛 NPE；该 NPE 发生在 verify 中途，Matcher 栈未被消费而泄漏，连带本批其余用例报 `UnfinishedVerificationException` / `InvalidUseOfMatchersException`。
  → 统一改 `captor.capture() ?: PageRequest.of(0, 1)`；确认 `mediaOnly`/`emptyContent` 两处失败纯属级联污染（同文件、同 Matcher 栈），修复后一并转绿。
- **`ArgumentCaptor` 抓 `Map` 必须强转目标类型**：
  `ArgumentCaptor.forClass(Map::class.java)` 推断为 `ArgumentCaptor<Map<*,*>>`，其 `capture()` 返回 `Map<*,*>?`，与方法的 `Map<String, Any?>?` 参数因 **key 不变性**不兼容，编译失败。
  → 声明时即 `as ArgumentCaptor<Map<String, Any?>>`，`captor.value` 落为 `Map<String, Any?>`，索引取 `CommandKey.*` 正常。
- **复用 captor 跨多次 verify**：`listMessages` 调两次，每次 `requireOwned`/`findByDeviceId...` 各调用一次，须 `times(2)` 而非默认 `times(1)`。
