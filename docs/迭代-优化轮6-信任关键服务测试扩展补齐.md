| R8 | 编译铁律（本仓**无 mockito-kotlin**） | `whenever(...)` 不可用（未引入 mockito-kotlin 扩展，报 `Unresolved reference: whenever`）；`InvocationOnMock` 不支持 `a[0]`/`args[1]` 数组索引（报 `No get method providing array access`），须用 `a.arguments[0]`/`args.arguments[1]`；`Optional` 需显式 `import java.util.Optional`，否则 `Unresolved reference: Optional` | 中（编译失败） | 见三、踩坑闭环 |

### 2.3 `AdminPermissionServiceTest.kt`（新建，13 例全绿）

## 三、验证

- `:padguard-server:compileTestKotlin` 通过；定向重跑四份测试类，**46/46 PASSED**（`tests="6"/"9"/"13"/"18" failures="0" errors="0"`，XML 已确认）。
- 路线纪律：Mockito 隔离全部依赖 + 真实实体构造（`Device`/`AuditLog`/`Admin`/`AdminRoleOverride`/`CustomAdminRole` 等），**不加载 Spring 上下文**（规避全量集成 OOM，符合项目约 626 例集成测试跑不下的约束）。
- `afterCommit { block }` 在无 Spring 事务时**立即执行** block，故 `unbind` 下游副作用（purge/审计/清 retained/推 config）直接落到 mock；`@Transactional` 在无 Spring 代理下按普通方法执行——两者共同保证纯单元测试可走通。
- **踩坑闭环（铁律更新，本轮命中 R5/R6/R7/R8）**：
  - `assertThrows`：**必须用 `assertThrows(BizException::class.java) { ... }`**（Java 风格重载），**不要**用 Kotlin 泛型 `assertThrows<BizException> { ... }`——后者在 lambda 返回非 Unit 时触发重载歧义编译失败（R5）。
  - Kotlin 非空参数 + Mockito 占位（R6，再次确认并强化）：非空 `String` 用 `eq(x) ?: x`（`when` **与 `verify` 两侧都要补**）；非空 `Pageable` 用 `any(Pageable::class.java) ?: PageRequest.of(0,1)`；非空 `Map` 用 `any() ?: emptyMap()`；带非空位的方法（如 `record` 的 `action`/`result`）逐位补 `eq(...) ?: ...` / `any() ?: "SUCCESS"`。缺 `?:` 必 NPE 并级联污染同测试类其余用例。
  - **Kotlin 默认参数方法 stub（R7，新踩）**：对 `fun f(x: T = default)` 这种带默认参数的方法，**禁止用无参形式 stub**（`when(mock.f()).thenReturn(...)` 匹配不到生产调用，因为编译器把 `f()` 降为 `f(defaultValue)`）。须用 `when(mock.f(anyX())).thenReturn(...)`（如 `takeTimedOut(anyLong())`）。
  - **编译铁律（R8，本仓无 mockito-kotlin）**：`whenever(...)` 不可用→改 `` `when`(...) ``；`InvocationOnMock` 不支持 `a[0]`/`args[1]` 数组索引→改 `a.arguments[0]`/`args.arguments[1]`；`Optional` 须 `import java.util.Optional`（这几个在轮 5 的 CommandServiceTest/UnlockServiceTest 已证实，本轮四新类复现并闭环）。

## 五、结论
