**期望看到的成功日志**（用于自动接续判定，见第 4/5 节）：
- `SpecialPermission: open settings for <key> (N candidates)`
- `RomSettings: settings entry resolved: <action 或类名>`
- `ConsentReturnPresenter: consent target granted after ...ms: <名称>`（可检测项）
- `ConsentReturnPresenter: returned from OEM settings after ...ms: <名称>`（不可检测项）
- `ConsentReturnPresenter: consent screen returned via task-move / activity-start`

## 3. 授权清单与本机适用矩阵（核对表的依据）

### 3.1 目录内 8 项（`SpecialPermission`，全 App 唯一事实源）

| # | key | 名称 | minSdk | 目标机 API29 | 可检测 | 官方入口 / 完成判定 |
|---|---|---|---|---|---|---|
| P-01 | `overlay` | 悬浮窗 | M(23) | 适用 | 是 | `ACTION_MANAGE_OVERLAY_PERMISSION` + package data；`Settings.canDrawOverlays` 变 true |
| P-02 | `usageStats` | 使用情况访问 | L(21) | 适用 | 是 | `ACTION_USAGE_ACCESS_SETTINGS` + package data；AppOps `GET_USAGE_STATS = MODE_ALLOWED` |
| P-03 | `installPackages` | 安装未知应用 | O(26) | 适用（**无 DO**） | 是 | `ACTION_MANAGE_UNKNOWN_APP_SOURCES` + package data；`canRequestPackageInstalls` |
| P-04 | `accessibility` | 无障碍服务（操作闸门） | L(21) | 适用 | 是 | `ACTION_ACCESSIBILITY_SETTINGS`（+ `EXTRA_COMPONENT_NAME` 尽力深链）；`GuardA11y.isEnabled` |
| P-05 | `batteryOptimization` | 电池优化白名单 | M(23) | 适用 | 是 | `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`（列表页，家长需自己选本应用）；`isIgnoringBatteryOptimizations` |
| P-06 | `exactAlarm` | 闹钟和提醒（精确闹钟） | **S(31)** | **不适用**（API29 无此开关，不得出现在清单） | 是 | `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` + package data；`canScheduleExactAlarms` |
| P-07 | `appNotifications` | 通知 | O(26) | 适用 | 是 | `ACTION_APP_NOTIFICATION_SETTINGS` + `EXTRA_APP_PACKAGE`；`areNotificationsEnabled` |
| P-08 | `oemBackground` | 后台运行（自启动 / 后台弹出界面） | L(21) | 适用（HUAWEI） | **否** | 无官方页 → 华为 `systemmanager` 私有页 → 应用详情兜底；完成判定＝**离开并回到前台**，状态 `CONFIRMED` |

> **目标机预期适用 7 项**（8 项减去 P-06）。若按 `docs/设备所有者(DO)部署SOP.md` 预置了 DO，P-03 会被 `appliesTo` 剔除 → **6 项**。两条路径都要在第 5 节 E-11 覆盖。
> P-08 是**唯一** `detectable=false / optional=true / requiredForReauth=false` 的项：不参与掉失自愈，界面如实标「已带您前往设置（请确认开启）」，**不得**显示"已开启"。

### 3.2 目录外的 5 个流水线环节（`OneTimeConsentViewModel`，同样要逐项验）

| # | key / 环节 | 触发条件 | 交互形态 |
|---|---|---|---|
| A-01 | DO 预置页 | **release 包**且 `!isDeviceOwner && !doPromptAck` | `DoProvisioningScreen`，按 SOP 预置或家长确认已知风险 |
| A-02 | `deviceAdmin` 设备管理员 | `ControlMode.LEGACY` | `ACTION_ADD_DEVICE_ADMIN` 系统确认页，点「激活」 |
| A-03 | `runtimePermissions` | 运行时权限有缺 | 系统弹窗序列；共 定位×2 / 相机 / 麦克风 / 存储×2（API≤32）/ 通知（API≥33） |
| A-04 | `webGuardVpn` 上网防护 | `VpnService.prepare()` 返回非空 | 系统确认框，勾「信任此应用」→ 确定 |
| A-05 | `mediaProjection` 屏幕采集 | `needsCapture()` 为真 | MediaProjection 系统确认框 |

> **装机顺序**：A-01（release）→ 首次装机点一次「同意并授权」→ A-02 → A-03 → A-04 → P-01…P-08（按 `applicable` 过滤、按声明顺序）→ A-05 → `finish()`。
> DO 机型上 A-03 走 `runSilentGrant()` 静默授予，不弹窗。

## 4. 真机逐项核对表（核心）

### A 组 · 流水线前置与系统确认类

| 结果 | 编号 | 操作 | 通过标准 |
|---|---|---|---|
| □ | A-01 | debug 包首启 / release 包首启各一次 | debug 不出现 DO 预置页；release 出现 `DoProvisioningScreen`，按 SOP 预置或确认风险后**能正常进入下一步**，不卡死 |
| □ | A-02 | 首次装机停在第一屏 | 需家长主动点一次「同意并授权」才开始；**不是**自动开跑（合规要求） |
| □ | A-03 | 点「同意并授权」后观察设备管理员 | 自动拉起激活页，点「激活」后**无需按返回**自动回到授权页并跳下一项；日志出现 `consent screen returned via ...` |
| □ | A-04 | 管理员激活页上点「取消」 | 不无限重试、不崩溃；该项标「已跳过」，其余项照常走完；冷启动**不再**被反复弹回授权页（`daPromptAck` 已落） |
| □ | A-05 | 运行时权限弹窗序列 | 依次弹出且**序列期间不推进**；全部答完后自动继续；故意拒绝其中一项后流程降级继续、不卡「正在自动配置」 |
| □ | A-06 | VPN 确认框 | 弹得出、勾「信任」点确定后自动接回；取消后标跳过且后续照常走完 |
| □ | A-07 | 屏幕采集确认框 | 弹得出、确认后自动收尾；`finish()` 后常驻通知刷新为最新状态，不残留「仍未授权」之类陈旧文案 |

### B 组 · 7 项特殊权限逐项（目标机 EMUI10 / API29）

| 结果 | 编号 | 项 | 操作与通过标准 |
|---|---|---|---|
| □ | P-01 | 悬浮窗 | 自动落到「显示在其他应用上层」的**本应用**开关页（不是几十项全量列表）；拨开后**不按返回**，≤5s 内自动回授权页并跳下一项；清单该项变「已到位」 |
| □ | P-02 | 使用情况访问 | 落到「使用情况访问」的本应用页；列表里**能找到「护航成长」**（验证 Manifest 声明生效）；开启后自动接续 |
| □ | P-03 | 安装未知应用 | 落到「安装未知应用」的本应用页；开启后自动接续。（若已预置 DO，本项应**不出现**） |
| □ | P-04 | 无障碍服务 | 落到「无障碍」列表或本服务详情页；**手动找到并启用**后自动接续；特别注意：直接落到服务详情是「尽力深链」，落到列表页也算通过，只要不崩、不闪退 |
| □ | P-05 | 电池优化白名单 | 落到「不受电池优化限制的应用」列表；切到「所有应用」找到本应用并设为**允许**；加白后自动接续。注意此项**未声明** `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，只能由家长手选，属预期 |
| □ | P-06 | 精确闹钟 | **API29 目标机上不得出现此项**；确认「授权总览」里也没有。另找一台 **API 31+** 设备（见第 6 节）验证能落到「闹钟和提醒」页并回读 `canScheduleExactAlarms` |
| □ | P-07 | 通知 | 落到本应用的「应用通知」设置页；开启后自动接续。**追加测试**：先在系统里把通知彻底关掉再回到向导，应能重新进入并补开（验证「不再询问」永久拒绝后的补开入口） |
| □ | P-08 | 后台运行（厂商项） | 落到华为「启动管理 / 受保护应用」私有页（日志 `settings entry resolved: com.huawei.systemmanager/...`）；把自启动、关联启动、后台活动全设为允许后**按返回**或点兜底通知 → 自动跳下一项；清单该项显示 **`CONFIRMED`「已带您前往设置（请确认开启）」**，**绝不能**显示「已开启」；ELSE 若退到应用详情页，记 P1 但不算失败 |

## 5. 端到端场景回归

| 结果 | 编号 | 场景与步骤 | 通过标准 |
|---|---|---|---|
| □ | E-01 | **全新装机全流程**：清除数据 → 装包 → 绑定 → 走完第 4 节 A/B 组 | 一次流水线收全所有项，无死循环、无卡「正在自动配置」、无崩溃 |
| □ | E-02 | **掉授权自愈**：装机完成后到系统里关掉「使用情况访问」→ 等待 ≤15s 的 `GuardService` tick | 日志 `AuthorizationKeeper: authorization dropped, items=[usageStats...]`；冷启动/回前台被 `reauthRequired → OneTimeConsentScreen(autoStart=true)` 拉回，**只补缺失项**，已授予项显示为已到位不重弹 |
| □ | E-03 | **掉授权自愈（运行时权限 / 无障碍）**：分别关掉一项运行时权限、关掉无障碍服务 | 运行时权限由 `grantAll()` 尝试重授；无障碍由 `a11y` 重开引导；必缺项才拉回授权页 |
| □ | E-04 | **跳过不骚扰**：装机时明确跳过 P-08（厂商项）与一项可检测项，然后多次冷启动 | 跳过项不再每轮自检被拉回；只有「曾授予又掉」的项才触发自愈（`AuthorizationLedger.needsReauth` 口径） |
| □ | E-05 | **一键补齐**：我的 → 授权总览 → 一键补齐 | 列出的缺失项与流水线实际带去办的项**完全一致**；点击后进入与装机相同的自动接续流程，不另写跳转链 |
| □ | E-06 | **授权总览准确性**：总览页与 `SpecialPermission.applicable()` 对照 | 本机显示 **7 项**（无 DO）；每项「已到位 / 待确认」与系统实际开关一致；不存在写死的旧权限名 |
| □ | E-07 | **返回后状态刷新**：从设置页开完权限返回「我的」页 | 状态即时刷新为新值（验证 `RefreshDeviceStateOnResume`），不再出现「明明开了界面还说未开启」 |
| □ | E-08 | **版本升级补跑**：把 `consentVersion` 置于 1（模拟存量设备）→ 升级到本包 | 触发一次补引导；**已开启的项按真实状态跳过**，只补新增/缺失项；不要求家长把 7 项重做一遍 |
| □ | E-09 | **通知永久拒绝**：在系统里把通知设为「不再询问」式永久关闭 → 从总览补开 | 不再弹第二次运行时权限框，直接落到 `ACTION_APP_NOTIFICATION_SETTINGS`；开启后状态回读为已到位 |
| □ | E-10 | **杀进程 / 重启 / 飞行模式**：授权中途杀进程；装机后重启；飞行模式整天 | 重启后能从断点续跑不重复；飞行模式下本地管控与时间管控仍生效（不改系统时间则不受影响）；联网后服务端策略权威覆盖 |
| □ | E-11 | **DO 与软管控双路径**：按 SOP 预置 DO 后重走全流程 | DO 下：A-03 静默授予不弹窗、P-03 不出现（适用项变 6）、A-02 按 `ControlMode` 判定；软管控下 A-02 出现。两条路径都能走完 |
| □ | E-12 | **升级后常驻通知**：全流程结束看通知栏 | 不残留「卸载防护未开启」「屏幕采集未授权」等陈旧/僵尸通知；`GuardService.refreshPermissionNotice` 已刷新 |

## 6. 厂商 / 版本适配矩阵（可分批，但 P0 项必须先做完）

> 只有目标机（华为 EMUI10 / API29）是**必测**。其余行有设备才测；没设备必须如实填「未覆盖」，**不得据此对外宣称「已适配所有厂商」**。适配层的设计保障是"四级降级不崩"，命中率是体验项。

| 结果 | 厂商 / 系统 | 期望 Vendor | 观察点 |

## 8. 不通过判定准则

### P0（阻断上线，必须修复后复测）
1. 任一 P 项点击后**打不开页面**或崩溃（`ActivityNotFoundException` / 设置页闪退 / 日志 `no activity to open settings`）。
2. 可检测项办完后**不自动接续**，需要家长手动按返回或再点一次；或出现「返回 → 又跳回同一项」的无限循环。
3. 权限**已授予却被清单判为缺失**（或反之），导致流程走不完或功能静默失效。
4. 授权掉失后 `AuthorizationKeeper` **未拉回**补授权，或把家长主动跳过的项每轮反复拉回。
5. 声明了却没引导 / 引导了却没声明（Manifest ↔ 目录不一致），表现为系统列表里找不到本应用。
6. API 30+ 设备上厂商私有页**全部退化**成应用详情页（本轮 `<queries>` 修复未生效）。
7. `CONSENT_VERSION_CURRENT` 未递增导致存量设备不补跑新增项。
8. 发布包 DO 预置页卡死、无法进入后续流程。

### P1（需产品书面接受才可带条件上线）
- 某厂商私有页未命中、降级到应用详情页（功能不丢，家长多两步）。
- 无障碍页只落到总列表（未深链到本服务），家长需自己找服务条目。
- 电池优化页只落到全量列表，需家长切「所有应用」再选本应用。
- 不可检测项（P-08）只能靠「按返回 / 点兜底通知」接续，无法回读开关真实状态。

### 已知边界（**不是缺陷**，写进用户说明即可，不作为不通过项）
- AppOps、无障碍、MediaProjection、精确闹钟、厂商私有开关：**Android 不允许任何应用（含设备所有者）代开**，必须家长在系统页亲手确认。自动接续靠「拨完即回前台」+「按返回/点通知」，不承诺零系统交互。
- 应用**无法阻止用户在系统设置里关闭权限**。"不会丢失"的准确含义是：持久化 + 全量自检 + 掉失自愈 + 自动拉回，不是"锁死不可改"。
- 目标机无 DO 时，改系统时间 / 安全模式 / 恢复出厂仍可绕过时段管控（家长端已有如实显示）。
- 厂商私有页 ComponentName 属未公开实现细节，不同 ROM 大版本可能改名；降级链保证"至少能打开一个页"，不保证"一定直达开关"。
