# PadGuard 发布运行手册（2026-11-11）

> 一句话流程：**门禁 → 构建 → 签名注入 → 部署 → 探活 → 真机回归 → 灰度 → 监控/回滚**。
> 配套脚本均在 `padguard-server/scripts/`（`launch-preflight.sh` / `device-regression.sh` / `clean-uploads.sh` / `gen-env-secrets.sh` / `backup-db.sh` / `gen-certs.sh` / `check-wechat-pay.sh` / `sync-mqtt-users.sh`）。
> 决策与合规外部阻塞项见 `docs/上线决策与合规执行清单-2026-11-11.md`。

---

## 0. 发布前自检（门禁，阻断级）

```bash
cd padguard-server
CI=true bash scripts/launch-preflight.sh
# 期望：服务端 1142/0、孩子端 223/0、家长端 115/0，结论 GO
# 任一 FAIL → 修复后再发布；CI=true 时脚本以非 0 退出，可接 CI 阻断。
```

> ⚠️ 历史坑：该脚本曾因 `ROOT` 解析错误静默跳过三端套件并误报 GO，已修复并实跑验证。若改动后门禁"秒过"，先确认三个 gradle 子日志确有 BUILD SUCCESSFUL。

## 1. 构建

### 1.1 服务端
```bash
cd padguard-server
./gradlew bootJar          # 产物 build/libs/app.jar
```
- 测试堆上限已在 `build.gradle.kts` 显式 `maxHeapSize="2g"`（用例翻倍后必需，否则远程容器用例随机 OOM）。
- home 档（demo 默认 false）每次启动会重置测试账号 `19371581808/201325` 为随机强口令并写入 `uploads/初始密码-请登录后修改.txt`——**不要用测试账号做生产验证**。

### 1.2 孩子端 / 家长端（release 必须注入接入点）
```bash
cd 护航成长
./gradlew :app:assembleRelease \
  -PBASE_URL=https://<域名>/api/v1/ \
  -PMQTT_BROKER=ssl://<域名>:8883
cd ../护航控制端
./gradlew :app:assembleRelease \
  -PBASE_URL=https://<域名>/api/v1/
```
- **孩子端路径多一段 `/api/v1/`**，家长端没有；debug 按网卡自动探测本机私网 IP，release 必须显式注入。
- 切勿 `assembleRelease` 不带接入点——会打出连不上服务端的包。

## 2. 生产配置与密钥

```bash
cd padguard-server
bash scripts/gen-env-secrets.sh   # 从 .env.prod.example 生成 .env，CHANGE_ME_* → openssl rand 强随机
                                  # 不覆盖已有 .env；微信商户等留空项保持空（=不启用渠道）
```
- **`.env` 已被 gitignore，绝不入库。** 备份到离线保险柜。
- 配置项：DB 连接（H2→生产 Postgres，U-12 待实测）、JWT/BCrypt 密钥、MQTT broker 凭据、文件存储路径、微信商户（按需）。

## 3. 部署（停服→替换→起服）

```bash
# 1) 先停旧服务（Windows 下 jar 被占用无法直接覆盖）
#    通过 start-server-guard.bat / 服务管理器停止 8090 端口进程
# 2) 备份当前产物与数据
bash scripts/backup-db.sh
cp deploy/app.jar deploy/app.jar.bak.$(date +%Y%m%d)
# 3) 替换并启动（home 档）
cp padguard-server/build/libs/app.jar deploy/app.jar
cd deploy && java -jar app.jar
# 4) 探活
curl -s http://127.0.0.1:8090/health   # 期望 ready=true
```

## 4. 真机回归（P0-2，硬阻塞）

```bash
cd padguard-server
adb devices                      # 确认真机已连接（孩子端已绑定）
PKG=com.padguard.child.debug bash scripts/device-regression.sh
# 自动项：
#   R-00 版本守卫/权限与组件探测（versionCode 与源码不一致直接 FAIL，防止验旧包）
#   R-02 飞行模式（结束后自动关闭飞行模式，避免后续联网项假失败）
#   R-03 强杀重启 / R-10 非DO 自愈
#   R-10A 无障碍一键清理静默自愈（需先 pm grant WRITE_SECURE_SETTINGS；未授权则 SKIP）
# 人工项：R-01/04/05/06/07/08/09/11/12/13 按脚本打印步骤点检
#   R-12 撤回同意后本地停采（心跳保留）；R-13 软/硬管控双闸门
STRICT=1 bash scripts/device-regression.sh   # 任一自动项 FAIL 以非 0 退出
```
- 脚本落 Markdown 报告与 logcat 证据到 `REPORT_DIR`（默认 `/tmp`），可直接附进上线评审记录。
- R-10A 是**破坏性回归**：会清空 `enabled_accessibility_services` 再等待最多 180s 自愈；仅应在已授予 `WRITE_SECURE_SETTINGS` 的目标机上执行。
- 设备仍装 **1.0.4**；加固包需真人装（EMUI 10 装包需解锁+人工确认）。**此项是公开上线前必须补齐的最后一环**。
- 改系统时间绕过「时段」属已知降级边界（受信钟 A1 防日切伪造、但墙钟时段可拨动），已在家长端能力说明中如实告知。

## 5. `uploads/` 清理（发布前）

```bash
cd padguard-server
bash scripts/clean-uploads.sh            # 仅报告孤儿（当前约 460 个测试样本 + 探针）
bash scripts/clean-uploads.sh --prune    # 移到隔离区（不真删），供人工复核后清空
```
- 权威清理以 DB 引用为准；文件名白名单为保守兜底。打包前清理避免把测试样本随版发布。

## 6. 灰度与监控

1. **先小批量**：10–20 个真实家庭（受控内测），观察 3–7 天无 P0 异常再扩量。
2. **监控**：服务端 `/health` 探活；MQTT 设备在线数；家长端「脱管提示」出现频次（R-10 软管控失效信号）；日切/额度异常日志。
3. **告警**：脱管、篡改系统时间、看屏授权被拒等事件应在家长端可见。

---

## 7. 回滚

- **服务端**：保留 `deploy/app.jar.bak.<date>`；停服→还原 jar→起服。Flyway 社区版无 `undo`，全部迁移单向 —— DB 回滚只能用 `backup-db.sh` 快照回灌，禁止假设存在 `down` 脚本。
- **孩子端/家长端**：应用市场「暂停发布 / 回退上一版本」；已装包通过热更新策略降级（若有）。
- **数据**：回滚前先 `backup-db.sh` 留快照，确保可回灌。

## 8. 安全加固核对（发布前必读）

- [x] 孩子端源码无硬编码密钥（`password = ""` 等为空，凭据均来自服务端/运行时）。
- [x] 孩子端 `usesCleartextTraffic=true` 仅用于**家庭局域网部署**（服务端跑家长电脑内网 http）；公网经 Nginx 终止 TLS，孩子端填 https 域名即加密——**不在公网强制 false**，否则废掉局域网场景。
- [x] 设备管理员/DO 为非必需增强；未激活时全部软管控照常工作，仅少防卸载等加固项。
- [ ] `owner=外部` 隐私政策法务复核、TLS 证书采购、微信商户资质、发布签名 keystore 离线备份（见合规清单）。
