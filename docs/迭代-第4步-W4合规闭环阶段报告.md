## 二、修复计划与改动位置

### 1. 数据模型与迁移（新增）
- **迁移** `src/main/resources/db/migration/V2026110901__compliance_data_rights.sql`
  - `devices` 加 `consent_revoked BOOLEAN NOT NULL DEFAULT FALSE`
  - `audit_logs` 加 `hash VARCHAR(64)` + 索引（历史行 hash=NULL，不参与链校验）
  - 新建 `appeals`／`account_deletion_requests` 两表（全 `IF NOT EXISTS/DEFAULT`，H2-MODE=PostgreSQL 与 PG16 双兼容）
- **实体**
  - `ExtraModels.kt`：新增 `Appeal`、`AccountDeletionRequest`；`AuditLog` 加 `hash`
  - `Models.kt`：`Device` 加 `consentRevoked`

### 2. 服务端逻辑（新增）
- `ComplianceService.kt`
  - `withdrawConsent` / `reinstateConsent`：撤回/恢复授权（置位 `consent_revoked`）。采用 **load 实体→改字段→save** 语义，与 `confirmAccountDeletion` 匿名化写法一致；**不新增 @Modifying 抽象方法**，以免向十余个测试 Fake 仓储扩散改动（规避 W2 已标记的 "fake implements whole repository" 技术债）。
  - `exportData`：结构化导出账号档案/设备/授权状态/本人申诉与注销请求，**手机号 `take(3)+"****"+takeLast(4)` 掩码**。
  - `requestAccountDeletion`：生成凭证 + **冷静期默认 2 天**（`padguard.compliance.deletion-cooldown-ms` 可配），幂等（已有 PENDING 未取消则返回原单）。
  - `confirmAccountDeletion`：复核凭证 → `purgeService.purge` 设备个人数据 → 删除设备行 → **匿名化 user（手机号/昵称/头像/邮箱/口令置随机、status=deleted、`tokenVersion+1` 吊销全部已签发令牌）**。
  - `cancelAccountDeletion`：冷静期内可反悔。
  - `submitAppeal` / `listAppeals` / `getAppeal`：`deviceId` 非空时经 `ownershipGuard.requireOwned` 归属校验。
- `ParentDataRightsController.kt`（9 端点，`/v1/compliance/...`）：withdraw、reinstate、export、account/deletion/{request,confirm,cancel}、appeals、appeals/{id}。
- `AuditService.kt`：`record()` 写 SHA-256 逐行哈希；新增 `verifyIntegrity(limit)` 批量检篡改（忽略历史 NULL hash 行）。
- `IngestService.kt`：`saveLogs` / `saveLocations` 开头加 `consentRevoked` 守卫——撤回后停止落库个人数据，并作为孩子端本地停采信号源（离线也生效）。

### 3. 测试（新增，全绿）
- `ComplianceServiceTest.kt`（7 例）：撤回/恢复置位与审计、导出掩码、注销幂等、注销级联清除+匿名化+令牌吊销、未知设备抛错、申诉落库。
- `AuditServiceHashTest.kt`（3 例）：record 写哈希、verifyIntegrity 检篡改、忽略历史 NULL hash 行。

## 三、无法仅靠代码解决的问题（必须外部拍板 / 高亮）

1. **数据导出时效性范围**：当前为「结构化 JSON 即时返回」，用量/位置/截图等**时序明细未包含**（单次响应过大会拖垮接口）。完整可下载包（异步生成 + 对象存储签名 URL）属二期批次，需排期。
2. **冷静期阈值**：2 天为「防误删产品决策」，**非 PIPL 强制**。法定仅要求「在合理期限内删除」，无冷静期强制；具体天数需法务/产品确认。
3. **审计哈希形态**：本轮为**逐行 SHA-256 哈希**（满足 PRD M14-3「哈希链/只写隔离之一」的哈希项），**非链式哈希链**；若要抗顺序篡改需升级为链式，属工程增强。
4. **外部资质（非代码）**：隐私政策、未成年人保护专项合规、ICP 备案、等保测评、应用商店（教育类）上架资质、微信支付/开放平台资质——需独立走法务与运营流程，不在本迭代代码范畴。
5. **PG16 迁移实测**：沙箱无 PG 实例，`V2026110901` 仅在 H2(MODE=PostgreSQL) 通过语法校验；**上线前预发环境需复跑 Flyway 验证**。

## 四、架构缺陷：两套方案（数据导出大文件）

| 维度 | 低成本（本期） | 长期（二期） |
|---|---|---|
| 形态 | 即时结构化 JSON（账号/设备/授权状态/诉求列表），手机号掩码 | 异步任务生成 zip（含时序明细），对象存储签名 URL 下载 |
| 触发 | 同步接口 | `POST /export` → 轮询/通知 → 下载链接 |
| 收益 | 立刻满足「查阅复制」法定权利 | 不阻塞主链路、可承载大数据量、可审计下载行为 |
| 成本 | 明细缺失，需二期补齐 | 需异步框架 + 存储 + 生命周期清理 |
