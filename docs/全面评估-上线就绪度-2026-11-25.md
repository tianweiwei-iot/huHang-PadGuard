## 二、三维复核结论

并行只读复核 **发布链路**、**功能完整性**、**性能容量** 三个维度，只收有文件+行号+可执行建议的真实问题，逐条二次核实，剔除误报。

### 2.1 功能完整性：无 P0 核心业务断裂 ✅
- 三条关键业务链均贯通：策略下发→孩子端执行→状态回执；支付→回调→权益→孩子端权益闸门→退款回收；风险检测→告警→推送→处置→状态更新。
- 3 项 P1（非上线阻断，属功能完整度）：
  - 策略版本历史/回滚/定时生效/批量下发：服务端端点齐全，家长端 UI 零接线（不影响基础管控）。
  - 内容管控：服务端 4 端点就绪，家长端与后台无入口；`UrlClassifier`/`ContentScanner` 仍为预留接口（当前靠本地域名级过滤）。
  - admin MFA：仍为 stub。
- 核实为**设计取舍、不计缺口**：`/sms/send` 空实现（运行期硬拒未接服务的短信登录，避免免密入口）、周期自动截屏未实现（按需截图已覆盖核心场景）、局域网直连看屏未实现（走服务端中转）。

### 2.2 性能容量：1 个需拍板的 P0 + 若干 P1
- **P0（容量口径，非代码缺陷）**：实时看屏是同步 Servlet 长连接，`while(true)` 逐帧读期间独占一个 Tomcat 工作线程（`StreamControllers.kt:51-82`）；拉流侧 `StreamingResponseBody` 走 Spring MVC 默认 `SimpleAsyncTaskExecutor`，无有界线程池（`WebConfig.kt` 未覆写 `configureAsyncSupport`）。而 `max-live-devices=1000`（`application.yml:72`）与容器默认 200 线程严重失衡：约 200 路并发推流即可占满容器线程，使家长端/后台/孩子端轮询与 `/health` 全部排队。
  - **定性**：这是“规模上来才会触发”的容量上限问题，需要压测数据与产品拍板（并发看屏到底放多少路），不是当前代码写错。修法：显式配 `server.tomcat.threads.max` 并使准入上限低于它；upload 改 Servlet 3.1 异步读；为 MVC async 配 `ThreadPoolTaskExecutor` + 拒绝策略。
  - **本轮动作**：列入上线前容量验证项，不在无压测数据时贸然改并发上限（改小会削弱功能、改大加剧风险）。
- P1（已定位，多数为“规模放大”隐患）：MQTT 验签每条查库无缓存、usage 日志每 10s 强制重算今日统计（家长不在线也白算）、WS 每次推送查用户表、媒体保留期清理全量加载、脱管告警去重集合解绑后残留、看屏累计流量 Map 常驻、9 个 `@Scheduled` 共享 4 线程、stream 端点无限流、关键状态均 JVM 本地（多副本放大 N 倍）。
  - 其中“看屏累计流量 Map”经核实是**注释明确的刻意设计**（历史流量榜，解绑时 `evict()` 清理），**不是泄漏、不改**。
  - “脱管告警集合”改动会影响去重语义与现有测试桩，收益（每 ID 几十字节）远小于回归风险，**本轮不改，记为已知残余**。

### 2.3 发布链路：1 个上线必挂 P0（本轮已修）
- **P0 已修**：`.env.prod.example` 与 `docker-compose.prod.yml` 把 `PG_USER` 默认为 `padguard`，而 `ProdConfigAssertion` 明确把用户名 `padguard` 判为弱口令并**启动即抛异常**。运维照模板只改密码、保留默认用户名时，app 起不来、nginx 连带失败。详见第三节。
- 误报已剔除：版本单调守卫挂在 `preBuild`（两端 `app/build.gradle.kts`），而 `testDebugUnitTest` 依赖链含 `preBuild`（`--dry-run` 实证），CI 会真正执行——无需修改 preflight。

### 家长端合规（同意链 + SDK 时序 + 数据权利）

1. **高德 SDK 时序（PIPL 第 14 条风险）**：`PadGuardApplication` 此前无条件 `MapsInitializer.updatePrivacyAgree(this, true)`——用户在同意页点"不同意"之前，SDK 已被宣告"已同意"。改为按 `PrivacyConsentPrefs.isAgreed()` 真实状态同步；新增 `AmapPrivacyCompliance.sync()` 作为唯一出口，`agree()`/`revoke()` 双向同步。
2. **政策与协议拆双版本**：原先单一 `KEY_VERSION`，协议不变、政策小改也会逼用户重签，反之政策变了但常量没动则旧同意继续放行。改为 `CURRENT_POLICY_VERSION=2.1.0` + `CURRENT_TERMS_VERSION=1.1.0` 独立留痕，两者任一不匹配即视为未同意。
3. **政策升版强制重勾**：导航层起始页由 `user != null` 改为 `user != null && consentAgreed`，已登录但留痕版本过期者退回登录页重勾（此前老用户升级后带着旧同意直接进主页，升版重勾形同虚设）。
4. **发码也过同意闸门**：`LoginViewModel.sendSmsCode` 前置 `consentGate`，避免"未同意先发短信"的采集动作。
5. **随包法务文本自动化**：Gradle `syncLegalAssets`（`preBuild` 依赖）把仓库根 `隐私政策.md`/`用户协议.md` 同步进 `assets/legal/`，杜绝人工 `cp` 漏更；`verifyLegalPlaceholders` 在 `assembleRelease`/`bundleRelease` 前扫描 `【上架前填写` 占位符并**阻断发布**（`-PALLOW_LEGAL_PLACEHOLDERS=true` 或 `CI=true` 可放行演练）。
6. **权限披露补全**：隐私政策新增 11 条特殊权限（通知使用权、无障碍、VPN 仅本地、安装未知应用、精确闹钟、开机自启、全屏通知、结束后台进程、NFC、`WRITE_SECURE_SETTINGS` 等）+「通知标题（可选，默认关闭）」采集说明，并明确"不读取界面文本"；`ComplianceManifestContractTest`（3 例）把 Manifest 快照（`allowBackup=false`、`exported` 恰 2 个、家长端权限恰 3 项）与政策版本钉死。
7. **撤回同意分两层**（新增，本轮补齐）：
   - 设备采集撤回 `withdrawConsent`（服务端停落库 + 下推孩子端）**不清会话**——家长仍要管理其他设备，清了就是"撤回采集被踢下线"。
   - 新增应用级 `revokePolicyConsent`：清本地留痕 + 停用高德 SDK + `clearWithReason()` 结束会话，原因经 `sessionNotice` 显示在登录页横幅（与令牌失效同一出口）。PIPL 第 15 条要求撤回后不得继续处理，只改 UI 不结束会话属假撤回。
8. **注销的端上删除闭环**：此前只清 JWT 与账号历史，孩子截图（Coil 磁盘缓存）与按租户下发的静态配置仍留本机——服务端删了、端上还能翻到，删除权未落地。新增 `clearLocalPersonalData()`：失效 `StaticConfigCache` + 清 Coil 内存/磁盘缓存，并**排在清 token 之前**（清 token 会弹栈取消 `viewModelScope`，其后的清理会被吞掉）。`ServerPrefs` 有意不清（服务器地址是部署配置，清掉会让自建服务器家长"注销后连不上又无入口改地址"）。`隐私政策.md` 第七节同步补两条撤回路径的差别。

### 禁逆新增

- 代理/VPN 与 HOME 角色检测**不得在未绑定时上报**（`TamperDetectorBindingGateTest` 锁）；否则新装设备必然产生两条误报。
- 上行字段长度/大小边界只在 `UplinkValidation` 一处定义，两个上行入口共用；禁止在控制器里另写一份阈值。
- 政策级撤回必须 `revoke()` + 结束会话**同时发生**；设备采集撤回**不得**动会话。二者不可合并成一个按钮。
- 注销的本地清理必须排在 `tokenManager.clear()` 之前，否则协程随弹栈被取消，清理静默丢失（`DataRightsWiringContractTest` 钉顺序）。
- 家长端法务文本只走 `syncLegalAssets` 同步，禁止手工复制进 `assets/legal/`；release 占位符门禁不得为了"能打包"而全局关掉。
