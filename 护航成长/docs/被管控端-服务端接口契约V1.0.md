# 平板管控系统 · 被管控端（护航成长）↔ 服务端 接口契约

| 项 | 值 |
|---|---|
| 文档版本 | V1.0 |
| 适用端 | 被管控端 APK（applicationId: `com.padguard.child`） |
| 通信模式 | **MQTT 长连接（实时通道） + HTTPS（大包通道）** |
| 目标平台 | Android 8.0 – 14（minSdk 26 / targetSdk 35） |
| 状态 | 待服务端确认 |

> **为什么拆成两条通道**
> MQTT 负责"高频、小包、要实时"的数据（心跳、指令下发、指令回执），天然具备断线重连、QoS 分级、省电省流特性，千台设备规模下服务端压力远小于 HTTP 轮询。
> HTTPS 负责"低频、大包、要可靠"的数据（全量策略包、批量日志、截图），走标准 REST 便于做鉴权、限流、审计。
> 参考实现：Headwind MDM（Apache-2.0）采用同样的 MQTT + HTTPS 双通道架构。

## 1. 通信架构

```
┌──────────────────────────────────────────────────────────────┐
│                        被管控端 APK                            │
│  ┌────────────┐  ┌──────────────┐  ┌───────────────────────┐  │
│  │ MQTT 客户端 │  │ HTTPS Client │  │ 本地策略引擎 + 离线缓存 │  │
│  │ (Paho QoS1)│  │  (OkHttp)    │  │   (断网仍可执行管控)    │  │
│  └─────┬──────┘  └──────┬───────┘  └───────────┬───────────┘  │
└────────┼────────────────┼──────────────────────┼──────────────┘
         │                │                      │
    ┌────▼─────┐    ┌─────▼──────┐         ┌─────▼──────┐
    │  MQTT    │    │  REST API  │         │ 本地 Room  │
    │  Broker  │    │  网关      │         │  加密存储   │
    └────┬─────┘    └─────┬──────┘         └────────────┘
         └────────┬───────┘
          服务端业务层
```

**降级策略**：MQTT 不可达时（校园防火墙封 1883/8883 端口），终端自动退化为 HTTPS 轮询（默认 60s，可远程配置），保证管控不断链。终端在心跳里上报当前 `transportMode`，便于服务端感知降级设备。

## 2. 设备标识与鉴权

### 2.1 设备标识

| 字段 | 生成方式 | 说明 |
|---|---|---|
| `deviceId` | 服务端绑定成功后下发（UUID） | **全局唯一业务主键**，后续所有请求以此为准 |
| `deviceSn` | `android.os.Build.SERIAL` / `Build.getSerial()` | 硬件序列号，Android 10+ 需 READ_PRIVILEGED_PHONE_STATE，取不到时上报空串 |
| `imei` | 仅蜂窝版平板可取，需 `READ_PHONE_STATE` | 取不到时上报空串，**不参与唯一性判定** |
| `fingerprint` | `SHA256(ANDROID_ID + Build.BOARD + Build.BRAND)` | 本地生成的稳定指纹，用于刷机后识别同机 |

### 2.2 鉴权令牌

绑定成功后服务端返回：

```json
{
  "deviceId": "d7f3a1c2-8b44-4e91-9a02-5c1de8f7b3aa",
  "deviceToken": "eyJhbGciOiJIUzI1NiIs...",
  "mqttUsername": "d7f3a1c2-8b44-4e91-9a02-5c1de8f7b3aa",
  "mqttPassword": "mk_9f2b7c4e1a8d6...",
  "hmacSecret": "hs_3a9f8b2c1d7e5...",
  "expiresAt": 1785000000000
}
```

- `deviceToken`：HTTPS 请求头 `Authorization: Bearer <deviceToken>`
- `mqttUsername` / `mqttPassword`：MQTT CONNECT 的用户名密码
- `hmacSecret`：指令签名校验密钥，**仅存于设备本地加密区，永不上传**

## 3. MQTT 设计

### 3.1 连接参数

| 参数 | 值 |
|---|---|
| Broker | `ssl://mqtt.padguard.cn:8883`（测试环境 `tcp://<host>:1883`） |
| ClientId | `pgc_{deviceId}` |
| KeepAlive | 90s |
| CleanSession | false（保留离线期间的 QoS1 指令） |
| 遗嘱消息 | topic `pg/v1/{tenant}/up/{deviceId}/status`，payload `{"online":false}`，QoS1，retain=true |

### 3.2 Topic 规范

统一前缀：`pg/v1/{tenantId}/{direction}/{deviceId}/{type}`

#### 下行（服务端 → 终端）

| Topic | QoS | 用途 |
|---|---|---|
| `pg/v1/{tenant}/down/{deviceId}/command` | 1 | 远程指令（锁屏、重启、截屏、改策略等） |
| `pg/v1/{tenant}/down/{deviceId}/policy` | 1 | 策略更新通知（payload 仅含版本号，终端再走 HTTPS 拉全量） |
| `pg/v1/{tenant}/down/{deviceId}/config` | 1 | 运行参数调整（心跳周期、上报周期、传输模式） |
| `pg/v1/{tenant}/broadcast/{groupId}/command` | 1 | 分组批量指令（课堂全员锁屏） |

#### 上行（终端 → 服务端）

| Topic | QoS | 用途 |
|---|---|---|
| `pg/v1/{tenant}/up/{deviceId}/heartbeat` | 0 | 30s 心跳（可远程配置 5s–300s） |
| `pg/v1/{tenant}/up/{deviceId}/ack` | 1 | 指令回执 |
| `pg/v1/{tenant}/up/{deviceId}/event` | 1 | 违规/告警事件（高危，优先上报） |
| `pg/v1/{tenant}/up/{deviceId}/status` | 1 | 上下线状态（遗嘱消息复用此 topic） |

## 4. 数据格式

### 4.1 指令包（下行）

```json
{
  "msgId": "cmd_01HZ8X9K2M3N4P5Q6R7S8T9V0W",
  "type": "LOCK_SCREEN",
  "version": 1,
  "timestamp": 1785000000000,
  "expiresAt": 1785000300000,
  "priority": "HIGH",
  "payload": {
    "reason": "已到达就寝时间",
    "unlockAt": 1785036000000
  },
  "signature": "base64(HMAC-SHA256(msgId|type|timestamp|payloadJson, hmacSecret))"
}
```

**校验规则（终端侧强制执行）**：
1. `expiresAt` 早于当前时间 → 丢弃（防重放）
2. `signature` 校验失败 → 丢弃并上报 `INVALID_SIGNATURE` 告警
3. `msgId` 在最近 500 条中已存在 → 丢弃（幂等），但仍回执 `DUPLICATED`
4. 以上任一失败均**不执行**指令

### 4.2 指令回执（上行）

```json
{
  "msgId": "cmd_01HZ8X9K2M3N4P5Q6R7S8T9V0W",
  "deviceId": "d7f3a1c2-...",
  "status": "SUCCESS",
  "executedAt": 1785000003456,
  "errorCode": null,
  "errorMessage": null,
  "retryCount": 0
}
```

`status` 枚举：`SUCCESS` / `FAILED` / `UNSUPPORTED`（当前权限模式不支持）/ `DUPLICATED`

> `UNSUPPORTED` 很关键：终端存在"设备属主(Device Owner)"与"用户态降级"两种权限模式，
> 部分指令（如静默安装）在降级模式下无法执行，服务端据此可统计出哪些设备需要重新部署。

### 4.3 心跳（上行）

```json
{
  "deviceId": "d7f3a1c2-...",
  "timestamp": 1785000000000,
  "policyVersion": 42,
  "transportMode": "MQTT",
  "controlMode": "DEVICE_OWNER",
  "network": {
    "type": "WIFI",
    "ssid": "Campus-Free",
    "signalLevel": 3,
    "ip": "10.20.31.88"
  },
  "battery": { "level": 78, "charging": true, "temperature": 31.5 },
  "storage": { "totalMb": 61440, "availableMb": 12880 },
  "memory": { "totalMb": 3896, "availableMb": 1120 },
  "screen": { "on": true, "brightness": 120 },
  "foregroundApp": "com.example.study",
  "location": { "lat": 30.5728, "lng": 104.0668, "accuracy": 12.5, "ts": 1784999990000 },
  "pendingLogCount": 37
}
```

- `controlMode`：`DEVICE_OWNER` / `PROFILE_OWNER` / `DEVICE_ADMIN` / `LEGACY`
- `pendingLogCount`：本地待上报日志条数，服务端可据此判断设备是否长期离线

### 4.4 告警事件（上行，QoS1）

```json
{
  "eventId": "evt_01HZ8X9K...",
  "deviceId": "d7f3a1c2-...",
  "type": "UNINSTALL_ATTEMPT",
  "level": "HIGH",
  "timestamp": 1785000000000,
  "detail": {
    "packageName": "com.padguard.child",
    "source": "SETTINGS"
  }
}
```

`type` 枚举：`UNINSTALL_ATTEMPT` / `FORCE_STOP_ATTEMPT` / `CLEAR_DATA_ATTEMPT` / `CLOCK_TAMPERING` / `ROOT_DETECTED` / `DEVELOPER_OPTIONS_ENABLED` / `USB_DEBUG_ENABLED` / `BLACKLIST_APP_LAUNCH` / `BLOCKED_URL_ACCESS` / `TIME_LIMIT_EXCEEDED` / `PERMISSION_REVOKED` / `POLICY_APPLY_FAILED`

`level` 枚举：`HIGH` / `NORMAL` / `INFO`

## 5. HTTPS 接口

Base URL：`https://api.padguard.cn/api/v1`

统一请求头：
```
Authorization: Bearer <deviceToken>
Content-Type: application/json
X-Device-Id: <deviceId>
X-Request-Id: <uuid>       // 用于链路追踪
X-Timestamp: <millis>      // 与服务端时间差 >5 分钟时返回 409
```

统一响应包装：
```json
{ "code": 0, "message": "ok", "data": { }, "serverTime": 1785000000000 }
```
`code`：`0` 成功 / `40001` 参数错误 / `40101` 令牌失效 / `40301` 设备已解绑 / `40901` 时间不同步 / `50000` 服务端异常

### 5.1 设备绑定

`POST /device/bind`

请求：
```json
{
  "bindCode": "A7K9M2",
  "deviceSn": "HA1XYK9M2P",
  "imei": "",
  "fingerprint": "9f2b7c4e1a8d6...",
  "model": "Xiaomi Pad 6",
  "brand": "Xiaomi",
  "androidVersion": "13",
  "sdkInt": 33,
  "resolution": "1800x2880",
  "controlMode": "DEVICE_OWNER",
  "appVersion": "1.0.0"
}
```

`bindCode` 为管控端生成的 6 位一次性绑定码（有效期 10 分钟），扫码与手动输入两种入口共用此接口。

响应 `data`：见 §2.2 令牌结构。

错误码补充：`40302` 绑定码已失效 / `40303` 设备已绑定其他账号

> **P0 状态说明（被管控端内部 mock）**
> 当前被管控端 APK 尚未与家长端 App 联调，为让首次启动能走通「绑定→落本地→进入主页」整条链路，**欢迎页的「开始绑定」按钮固定使用演示绑定码 `123456` 走客户端 mock**：
> - 被控端把 `123456` 直接当作 `deviceId` 写入本地 DataStore（生成对应的 `deviceToken` / `mqttUsername` / `mqttPassword` / `hmacSecret`），**不调用 `POST /device/bind`**；
> - 家长端 App 落地生成真实 6 位绑定码后，需做两件事：① 移除 `BindViewModel.DEFAULT_TEST_BIND_CODE` 与 `startBindingWithDefaultCode()`，欢迎页跳到输入码页；② 走 `POST /device/bind`（本节请求结构），用真实 `bindCode` 拿到 `data.bindResult`。

### 5.2 时间同步

`GET /device/time`

响应 `data`：`{ "serverTime": 1785000000000 }`

终端用往返耗时折半补偿，计算 `offset = serverTime + rtt/2 - localNow`，用于防时间篡改检测。

### 5.3 拉取策略包

`GET /device/policy?currentVersion=41`

- 若 `currentVersion` 已是最新 → `code: 0`，`data: { "upToDate": true }`
- 否则返回全量策略包（见 §6）

> 策略采用**全量下发 + 版本号比对**机制（对应说明书「策略版本机制」）：
> 全量包便于离线缓存、可回滚、避免增量补丁在多设备间产生状态漂移。
> 策略包经 gzip 后通常 3–20KB，全量拉取成本可接受。

`type` 枚举：`APP_USAGE` / `APP_INSTALL` / `APP_UNINSTALL` / `URL_VISIT` / `URL_BLOCKED` / `SCREEN_ON_OFF` / `PERIPHERAL_CHANGE` / `SETTING_CHANGE_ATTEMPT` / `COMMAND_EXEC` / `UNLOCK_REQUEST`（详见 §9 临时解锁申请闭环）

## 7. 离线同步机制

1. 终端每次联网成功后**全量拉取**策略包，AES 加密写入本地 Room 数据库。
2. 断网期间，所有计时/拦截/锁机逻辑基于 `SystemClock.elapsedRealtime()` 本地闭环执行。
3. 行为日志、告警事件写入本地队列（`pendingLogCount` 持续增长）。
4. 网络恢复后按以下优先级增量同步：
   ```
   P1  HIGH 级告警事件（MQTT QoS1，立即）
   P2  指令回执（MQTT QoS1，立即）
   P3  普通行为日志（HTTPS 批量，每批 500 条）
   P4  截图/定位等大包（WiFi 下才传）
   ```
5. 服务端按 `logId` / `eventId` / `msgId` 做幂等去重，重复上报安全。

## 8. 安全约定

| 项 | 方案 |
|---|---|
| 传输 | 全链路 TLS 1.2+，MQTT 走 8883 端口 ssl |
| 指令防伪造 | HMAC-SHA256 签名，密钥绑定时下发，终端校验失败即丢弃并告警 |
| 防重放 | 指令带 `expiresAt`（默认 5 分钟）与 `msgId` 幂等窗口 |
| 本地存储 | 策略包与日志 AES-256-GCM 加密，存于应用私有目录 |
| 时间防篡改 | 服务端时间同步 + 单调时钟计时，见 §5.2 |
| 数据脱敏 | 截图、定位、网址仅授权管理员可见，服务端侧脱敏 |

## 9. 临时解锁申请闭环（V1.1 扩展）

> 设计意图：硬拦截一刀切会把孩子逼向对抗（借同学手机、找破解）。给一条"讲理由、等同意"的正规放行通道，反而更可控。
> 孩子端 P0-5 已实现并编译通过（被管控端 `com.padguard.child`），以下为**需服务端配合实现的契约**。

### 9.1 状态机（被管控端本地）
`PENDING`（申请中）→ `APPROVED`（家长同意）/ `REJECTED`（家长拒绝）/ `EXPIRED`（12h 超时自动失效，允许重新发起）。
超过 12h 未审批的请求自动置 `EXPIRED`，避免孩子永远卡在"申请中"。

### 9.2 上行：孩子发起申请（行为日志）
复用 §5.4 的批量日志通道（`POST /device/logs`），`type = UNLOCK_REQUEST`，payload 约定：

| 字段 | 类型 | 说明 |
|---|---|---|
| `requestId` | string | 被管控端生成，格式 `ur-` + 20 位十六进制（UUID 去横杠取前 20 位）；作为该次申请的全链路 ID |
| `packageName` | string | 申请放行的应用包名；**整机放行（时段锁/总时长耗尽）传空串** |
| `appLabel` | string | 应用展示名（被管控端已解析，避免服务端再查 PackageManager） |
| `durationMinutes` | string | 期望放行时长（分钟，字符串）；被管控端已夹到 5–120 |
| `reason` | string | 孩子填写的解锁理由（≤200 字，必填） |

服务端收到后**转为待审批工单**，工单 ID 建议直接复用 `requestId` 以便回执对齐。
上行走既有日志队列，天然具备离线堆积、批量上报、`logId` 幂等去重（§7）。

### 9.3 下行：家长同意（TEMP_UNLOCK 指令）
家长审批通过 → 下发 `TEMP_UNLOCK` 指令（§4.1 指令包）。
**新增要求**：指令 `payload` 必须带 `packageName`（与 9.2 同义；整机放行可空串）。
被管控端收到后：① 按 `durationMinutes` 临时放开限制；② 用 `packageName` 匹配并把本地对应 `requestId` 翻为 `APPROVED`。
家长不经申请主动放行时自然找不到匹配申请，被管控端静默跳过，属正常情况。

### 9.4 下行：家长拒绝（SHOW_MESSAGE 指令扩展）
家长拒绝 → 下发 `SHOW_MESSAGE` 指令（§4.1 指令包），**`payload` 额外带 `requestId`**（即 9.2 的 `requestId`）即表示"拒绝该申请"。
被管控端判断：若 `payload.requestId` 非空 → 把对应申请翻为 `REJECTED`；同时按 `body` 内容弹出家长消息作为拒因展示给孩子。
普通消息不带 `requestId`，行为与之前完全一致（no-op）。

### 9.5 服务端待办
1. 接收 `UNLOCK_REQUEST` 日志 → 落待审批工单（建议工单 ID = `requestId`）。
2. 审批通过后下发 `TEMP_UNLOCK`（带 `packageName`）。
3. 审批拒绝后下发 `SHOW_MESSAGE`（带 `requestId` + 拒因 `body`）。
4. 工单状态变更建议回写，便于家长端查看历史。
